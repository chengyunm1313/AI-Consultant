    AI 一天能做 5 台機甲？從白模、法線貼圖到骨架綁定，搞懂 AI 3D 建模的完整流程

    最近看到一位 3D 創作者分享，利用 AI 製作機甲模型，一天可以完成 5 台！ 他的製作方式大致是： 找一張喜歡的科幻機甲圖片。 讓 AI 把圖片轉成 3D 白模。 使用 GPT 生成材質貼圖。 把材質貼回 3D 模型。 最後拆分關節，讓機甲可以活動。 看起來好像很簡單，對吧？但我看到這套流程，第一個想到的問題是： 這跟之前研究的法線貼圖有什麼不同？既然 AI 都能生成 3D 模型了，為什麼還需要法線貼圖？又為什麼要拆關節？ 深入研究之後才發現，這其實涉及三種負責不同工作的技術：幾何形狀、表面細節，以及活動控制。它們可以組合成一套完整的 AI 3D 建模工作流。 今天就用製作一台「可以走路的機甲」當範例，從零開始解釋。 「一天 5 台」是本文起點的創作者分享，並非我的實測結果；目前未附該則分享的原始連結，因此不據此推算普遍產能。以下重點是拆解製作流程，以及釐清每個階段的完成標準。 一、3D 白模、法線貼圖與骨架，各自解決什麼問題？先想像我們要製作一台鋼彈。 3D 白模：真正做出立體形狀3D 白模就像拿黏土捏出一台鋼彈。你真的做出了頭部、胸甲、手臂、雙腿，還有背後的推進器。 這個模型可以旋轉 360 度，從正面、側面、背面觀看，因為它具有真正的立體幾何結構。 更精確地說，Mesh 是網格資料；白模則通常指尚未完成材質、以單純顏色檢查形狀的模型狀態。不是所有 Mesh 都是白色，也不是有了白模就代表模型已經適合動畫。 法線貼圖：讓表面看起來有細小凹凸假設鋼彈胸甲上有 100 顆小螺絲。把它們全部建模出來，會增加模型的幾何複雜度。 法線貼圖（Normal Map）利用 RGB 通道編碼表面法線方向，讓著色器計算光照時，呈現螺絲、刻痕、凹槽等凹凸效果。那些細節沒有因此真正凸出來。 換句話說，3D 白模負責真正的形狀，法線貼圖負責模擬細小的表面凹凸。 骨架綁定：建立模型的活動控制現在我們已經有一台外觀漂亮的鋼彈，但它還不會動。模型不會自動知道手肘在哪裡、膝蓋應該怎麼彎曲。 所以我們需要設定骨架、活動關節與旋轉軸，讓它能抬手、轉身、走路，甚至拿武器戰鬥。Rigging 是建立這套控制系統；動畫則是在時間軸上安排具體動作。 技術 解決什麼問題 3D 白模／網格 讓機甲真正具有立體形狀 法線貼圖 用較少幾何結構呈現表面細節 材質與貼圖 決定顏色、金屬感與粗糙程度 骨架綁定／控制設定 建立機甲可以活動的控制方式 動畫 讓機甲在時間軸上做出具體動作 這樣是不是比較容易理解了？ 二、既然 AI 能生成 3D 模型，為什麼還要人工處理？這是整個流程最重要的問題。 現在可以使用 Meshy、Tripo AI、Hunyuan3D 等工具，將圖片轉換成 3D 模型。丟一張科幻機甲圖片給 AI，它可能很快就能生成一台看起來相當完整的機甲。 但看起來像機甲，不代表它真的具備合理的機械結構。 舉個例子，當你想讓機甲舉起右手或走路，可能發現： 肩膀和胸甲黏在一起。 手肘沒有合理的活動空間。 膝蓋彎曲時，裝甲直接穿進大腿。 腳掌沒有正確的支撐點。 走路時雙腳亂甩，整台機甲像章魚一樣。 圖片轉 3D 的 AI 主要在推測外觀與幾何形狀，不一定能建立符合設計意圖的關節、活動限制與運動方式。即使工具提供自動拆件、綁定或動畫功能，也仍然要檢查結果。 所以 AI 生成的模型，經常需要人工整理。這也是為什麼這類工作流仍需要 3D 技術背景：生成速度加快了，後續的判斷與修正並沒有全部消失。 三、如何把 AI 機甲建模拆成完整六步驟？先把整條路線放在一起： 設計參考 → 生成網格 → 整理模型 → UV 與貼圖 → 關節與骨架 → 動畫及引擎測試。 本節先說明前三步，接著再分別拆解法線、材質與可動結構。這是方便理解的順序；實作時通常要在早期先規劃拆件，並在修改拓樸後重新確認 UV 與烘焙結果。 Step 1：使用 AI 設計機甲外觀首先需要一張機甲設計圖。可以使用 ChatGPT 生成圖片，也可以使用自己繪製的角色設定圖。 建議準備正面、側面、背面；如果可以，再補充 45 度角視圖。 因為一張圖片只能提供單一視角。正面圖片看不到背後的推進器，也無法準確判斷肩甲厚度，AI 必須自己猜測。 參考視角越完整，越有機會降低幾何推測錯誤，但前提是多視角的角色設計必須一致。不能正面是圓肩甲，背面卻變成另一台機甲。 此外，不是每個 Image-to-3D 介面都能一次接收多張圖。工具支援多視角時，再依它要求的格式輸入；不支援時，其他視圖仍可用於人工檢查。 這個階段的目標，是建立一份適合 3D 建模的設計參考，而不只是漂亮的宣傳圖。 Step 2：將圖片轉換成 3D 白模接著使用 Image-to-3D 工具。可以研究以下選擇： 工具 可以研究的用途 官方入口 Meshy 圖片轉 3D、文字轉 3D、AI 材質生成 Meshy／官方文件 Tripo AI 圖片或文字生成 3D，比較幾何生成與後續整理能力 Tripo AI Hunyuan3D-2 研究形狀生成、材質生成與自行部署工作流 官方 GitHub 專案 Meshy 與 Tripo 的官方網站均列有圖片轉 3D 功能；Hunyuan3D-2 則提供可研究的程式碼與模型使用流程。功能、版本、費用、部署需求及授權條款不同，使用前應確認對應版本；可取得程式碼不代表所有商用情境都沒有條件。 完成後會得到 3D Mesh，可能可以匯出 GLB、OBJ 或其他格式，實際支援依工具與方案而定。若後續需要骨架與動畫，也要選擇能保存相關資料的匯出格式，不能只看靜態網格是否成功匯出。 這時就能在 Blender 裡旋轉模型、檢查各角度。但先不要急著上材質，下一步可能更重要。 Step 3：整理模型的網格結構這一步叫 Mesh Cleanup，也可能涉及 Retopology。 **Mesh（網格）**由頂點、邊與面組成，可以想成用許多小多邊形拼出一台機甲；**Topology（拓樸）**則是這些元素如何排列、連接。 AI 模型可能外觀漂亮，網格卻不一定適合編輯或動畫。例如： 多邊形分布不均勻，或面數過高。 有多餘的內部幾何結構。 零件黏連，無法直接當成獨立關節操作。 關節附近的網格不合理。 整理時常遇到兩種技術： 技術 主要目的 需要注意 Decimation（減面） 減少多邊形數量 不保證減完就適合變形動畫 Retopology（重新拓樸） 重新安排網格結構 更重視後續編輯、變形或烘焙需求 如果模型太複雜，後續修改、骨架設定與即時渲染都會增加成本，遊戲資產尤其需要控制複雜度。不過，只製作靜態圖片時，不一定值得花大量時間重新拓樸；以剛體零件為主的機甲，也不需要每片裝甲都使用真人角色的變形佈線。 整理到什麼程度，取決於最終用途。 四、Step 4 的法線貼圖，應該在哪個階段使用？假設我們已經生成一台精細機甲，胸甲有螺絲、散熱孔、裝甲接縫、金屬刻痕。如果全部使用真正幾何呈現，模型可能相當複雜。 其中細小刮痕、淺凹槽、在目標觀看距離下不影響輪廓的螺絲頭，可以考慮用法線貼圖模擬。這就衍生出常見的遊戲資產製作方法： High Poly → Low Poly → Normal Map，也就是高精度模型 → 低面數模型 → 烘焙法線貼圖。 假設先做一台有 100 萬個多邊形的精細機甲，再製作只有 2 萬個多邊形的簡化版本。這些數字只是示意，不是所有機甲的標準面數。 簡化後，原本的螺絲、細刻痕可能消失。這時透過 Baking（烘焙），把高模的表面方向細節轉成適用於低模的法線貼圖，再套回低模材質。 低模雖然沒有那些真正的小幾何，在光線下仍能呈現類似凹凸。這能降低幾何成本、保留許多視覺細節，也方便配合不同精細程度的模型版本。但總效能仍受貼圖記憶體、材質數量、繪製次數等因素影響，不能只比較面數。 法線貼圖不能取代哪些結構？法線貼圖不會真正改變物體輪廓。 例如肩膀上有一根長砲管，不能只靠法線貼圖讓它伸出來。大型裝甲、武器、推進器、真正的開孔與活動關節，仍然需要合理的幾何結構。 它也不會替模型增加碰撞體積；當細節需要影響輪廓、接觸或近距離視差時，就要重新評估是否應保留幾何。 AI 生成法線圖，等於高低模烘焙嗎？不等於。 AI 可以生成看起來合理的表面凹凸，但要精準保留特定高模的細節，仍需要高低模對應、低模 UV 與正式烘焙流程。不能把任意一張紫藍色圖片直接當成正確法線資料。 在 Blender 中，法線圖通常會經過 Normal Map 節點再接入材質。切線空間法線圖需要對應的 UV，圖片應設定為 Non-Color，並確認與目標引擎的法線慣例相容。可參考 Blender 官方 Normal Map 節點手冊與烘焙說明；實際介面請對照自己使用的 Blender 版本。 五、Step 4 的材質與 UV，跟法線貼圖有什麼關係？法線貼圖其實只是材質系統的一部分。在 3D 製作中，常見的是 PBR（Physically Based Rendering，物理基礎渲染）材質。 用機甲來理解： 項目 用途 機甲範例 Base Color 決定基本顏色 紅色裝甲、白色胸甲、黑色關節 Metallic 表達金屬特性 金屬裸露區與非金屬塗層的差異 Roughness 控制反射的粗糙程度 低粗糙度反射較銳利，高粗糙度較模糊 Normal 模擬細小凹凸 刻痕、淺凹槽與裝甲紋路 Emission 表達自發光外觀 眼睛、能源核心與燈條 金屬零件表面若覆有一般非金屬漆，不能只因底下是金屬，就把整片外觀都設成裸金屬。Emission 能讓表面看起來發光，但是否照亮周圍、是否產生光暈，還取決於渲染器、燈光與後製設定。 UV 展開是什麼？想像把紙盒拆開攤平成一張紙，在紙上印上顏色與圖案，最後再折回紙盒。 UV 展開建立 3D 模型表面與 2D 圖片的對應關係。如果 UV 不正確，材質就可能拉伸、錯位或出現接縫。 因此，完整材質流程通常是： 模型整理 → UV 展開 → 產生或烘焙貼圖 → 設定 PBR 材質 → 檢查成果。 這也解釋了原本「使用 GPT 生成材質貼圖」需要補上的條件：產生一張金屬紋理圖片，不等於已經完成這台機甲的材質。 圖片仍要對應 UV，或經過投射、接縫修整與烘焙；Base Color、Roughness、Metallic、Normal 也必須各司其職。不能把帶著固定高光與陰影的彩色圖片，直接當成完整的 PBR 貼圖組。 「貼圖只能 512K」是什麼意思？原分享提到的「512K」需要特別注意，因為這不是清楚的貼圖像素尺寸寫法。它可能想表達 512×512 像素，也可能在描述檔案容量；沒有原始規格，無法確定。 兩者差異很大，而且貼圖解析度也不是越低越好： 常見像素尺寸 可以考慮的情境 512×512 部分小型物件或遠距離資產 1024×1024 部分一般中小型資產 2048×2048 需要較多近距離細節的資產 4096×4096 高細節需求，同時承擔較高記憶體成本 這些只是示意，不是固定標準。應考慮觀看距離、螢幕佔比、平台效能、貼圖數量與材質需求，也要區分磁碟壓縮檔大小與 GPU 載入成本。 不能直接說「不是做電腦遊戲，就只能使用 512 的貼圖」。 六、Step 5 為什麼要拆關節，還要設定骨架？因為目前做出來的機甲，可能只是一個外觀完整的模型。要讓它走路，就必須建立合理的活動結構。 機甲跟真人角色的綁定方式不完全相同。真人手肘彎曲時，皮膚會變形；但機甲的金屬裝甲，正常情況下不應該像橡皮一樣彎曲。 所以通常要讓不同部位可以獨立控制，例如胸甲、上臂、前臂、肩關節、大腿、小腿、膝關節與腳掌。這些可以是分離物件，也可以是同一網格內彼此不連通、由不同骨骼控制的剛體區塊。 接著設定旋轉樞紐、父子階層與活動限制： 手肘在合理角度內彎曲。 膝蓋不隨意向後折。 肩膀轉動時，肩甲配合移動。 腳掌落地時維持合理的接觸位置。 如果只把表面切開，沒有補齊遮住的零件、關節間隙與樞紐，動起來仍可能穿模或露出破洞。 有些機甲只需分離零件、旋轉樞紐與父子階層，就能完成基本動作；若使用骨架，也可以讓剛性裝甲跟隨單一骨骼，不一定要像皮膚一樣做平滑蒙皮變形。軟管、線材等需要彎曲的部分，則另行處理。 **機甲建模還涉及機械結構與運動設計。**拆分不正確，即使外觀很漂亮，動畫仍可能很奇怪。 Step 6：製作動畫，並到引擎中驗收骨架設定完成，還要在時間軸上安排動作。先從抬手、屈膝、腳掌落地等簡單測試開始，再做完整走路循環。 過程中要觀察裝甲是否穿模、腳是否滑動、重心是否合理，以及匯出後的骨架、材質與動畫是否一致。最後匯入 Godot 或其他目標環境，確認尺度、方向、播放與效能，才算走完這條流程。 能在 Blender 裡播放，不代表已完成遊戲整合；遊戲中的移動控制、碰撞與動畫切換，也需要另外設定與測試。 七、三種 AI 3D 建模流程，應該怎麼選？研究到這裡，我認為應該先決定用途，再選製作流程。 方案 A：快速展示型AI 圖片 → AI 生成白模 → AI 材質 → 3D 展示。 適合科幻角色展示、產品概念設計、靜態渲染與社群作品。若用於 3D 網頁，仍要視模型大小和裝置效能做適度整理。 GitHub 主專案 的介紹，目前包含多種影片製作 Pipeline、100 多種製作工具，以及 700 多份 Agent Skill 與製作知識檔案；數量會隨版本變動。它也整合圖片、影片、語音與素材服務，提供 Remotion、HyperFrames、FFmpeg 等合成與後製路徑，以及 Backlot 分鏡與進度工作台。 最重要的是，它可以搭配 Codex、Claude Code、Cursor 等能讀取檔案與執行程式碼的 AI Coding Agent 使用。 這代表我們不需要每個步驟都親自切換不同工具，而是可以讓 Agent 根據任務，選擇合適的製作流程。 例如，想製作科技知識影片，可以使用圖片、旁白與動態圖表；想製作城市紀錄片，則可以優先搜尋現有的動態素材，而不一定要花錢生成影片。 OpenMontage 的價值，是把不同工具組織成一個可以協作的製片團隊。 二、OpenMontage
