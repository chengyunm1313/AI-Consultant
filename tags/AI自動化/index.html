    OpenMontage 教學：一句話讓 Codex 幫你製作影片！從劇本、分鏡到配音與剪輯

    以前用 AI 做影片，你要自己當編劇、導演、剪輯師；現在，連製片流程都可以交給 AI Agent 協助！ 最近在 GitHub 發現一個很值得研究的開源專案，叫做 OpenMontage。 它不是另一個影片生成模型，而是一套可以搭配 Codex、Claude Code 等 AI Coding Agent 使用的自動化影片製作系統。 簡單來說，你只要告訴 AI： 幫我製作一支 30 秒的商品宣傳短片。 AI 就能依照工作流程，協助完成題材研究、劇本撰寫、角色與場景規劃、分鏡設計、素材取得、配音、剪輯與影片輸出。 更有趣的是，你還可以提供一支喜歡的 YouTube Shorts 或 Reels，讓 AI 分析它的敘事結構與剪輯節奏，再規劃一支原創影片。 對於正在製作 AI 網紅、AI 短劇、商品帶貨影片，或希望用 Codex 自動化剪輯的朋友，這套工具相當值得研究。 這篇文章就帶大家認識 OpenMontage，了解安裝與操作流程，並提供可以交給 Agent 使用的短影音提示詞。 版本與實測範圍：本文依 2026 年 11 月查閱的公開文件整理，教學提示詞為作者延伸設計，尚未逐一完成端到端實機測試。官方網站目前介紹 Windows 版 OpenMontage Studio，標示為私人 Alpha；本文安裝章節介紹的是 GitHub 原始碼工作流程。桌面產品、原始碼與其他同名儲存庫的功能及指令，請分別以各自文件為準。 一、OpenMontage 是什麼？如何讓 AI Agent 協調製片？OpenMontage 是一套開源的 Agentic Video Production System，也就是「代理式影片製作系統」。 它的核心概念，是把傳統影片製作團隊的工作流程拆解成多個階段，再交由 AI Agent 協調執行。 根據 GitHub 主專案 的介紹，目前包含多種影片製作 Pipeline、100 多種製作工具，以及 700 多份 Agent Skill 與製作知識檔案；數量會隨版本變動。它也整合圖片、影片、語音與素材服務，提供 Remotion、HyperFrames、FFmpeg 等合成與後製路徑，以及 Backlot 分鏡與進度工作台。 最重要的是，它可以搭配 Codex、Claude Code、Cursor 等能讀取檔案與執行程式碼的 AI Coding Agent 使用。 這代表我們不需要每個步驟都親自切換不同工具，而是可以讓 Agent 根據任務，選擇合適的製作流程。 例如，想製作科技知識影片，可以使用圖片、旁白與動態圖表；想製作城市紀錄片，則可以優先搜尋現有的動態素材，而不一定要花錢生成影片。 OpenMontage 的價值，是把不同工具組織成一個可以協作的製片團隊。 二、OpenMontage 能製作哪些影片？OpenMontage 不只支援 AI 動畫，也涵蓋多種常見的影片製作情境。以下整理主專案 README 列出的工作流範例，並非固定不變的完整清單。 影片類型 適合應用 Animated Explainer 知識型短影音、教學解說 Animation 動態圖文、品牌動畫 Avatar Spokesperson AI 虛擬人物口播 Cinematic 電影預告、品牌形象影片 Clip     別再一直建立 AI Agent 了！你真正需要的是學會管理 AI 員工

    未來最有競爭力的人，不一定是最會寫提示詞的人，而是最懂得管理 AI 團隊的人。 最近看到 Lauren Tan 分享 Grok Bot 的使用與團隊管理觀念，看完之後，我最大的感想是：我們是不是一直把 AI Agent 當成工具，卻忘了它其實更適合用管理員工的方式來安排工作？ 過去使用 ChatGPT，我們習慣問一個問題、得到一個答案。後來有了 Claude Multi-Agent 多代理架構時，很容易陷入一個迷思：既然可以建立很多 Agent，那是不是每個工作都應該有一個專屬 Agent？ 行銷一個、寫文章一個、查資料一個、寫程式一個、管理信箱一個……最後建立了十幾個 Agent，卻發現自己每天光是決定要找誰工作，就已經很累了。 這跟管理真實員工很像。員工越多，不代表生產力越高。如果沒有清楚的職責、工作流程與管理制度，反而會增加溝通成本。 的成功經驗，整理成可重用的 Skills？這是我特別喜歡的觀念：當你教 Bot 執行某項任務時，可以要求它把成功的工作流程整理成 Skills。 為什麼？因為 AI 有一個很常見的問題：今天教會它的事情，過了一段時間，換個對話或執行環境，可能又得重新說明。尤其當工作涉及很多細節時，光靠一大段提示詞，很難保證每次執行都一致。 這時候，Skills 就非常有價值。 例如，我經常需要將 AI 技術研究整理成部落格文章，再改寫成 Facebook 粉專貼文。與其每次重新交代「幫我研究技術背景、確認資料、加入實際應用案例，再改成適合粉專閱讀的語氣」，不如把這些步驟整理成一套內容製作 Skill。 以後只要告訴 AI： 使用我的科技文章 Skill，研究這個主題。 在支援這套 Skill、具備必要工具與資料權限的環境中，AI 就能依照既定流程執行。 一套實用的 Skill，至少應該交代： 什麼情況要使用，以及需要哪些輸入資料。 工作步驟與判斷規則。 預期輸出格式與驗收標準。 遇到缺漏或錯誤時如何回報。 哪些操作需要人類核准。 這些要素也與 Grok Bot 官方文件對 Skill 的說明一致：先完成一次任務、修正到可靠，再保存工作方法，最後才考慮自動化。 更進一步，也可以把不含機密或個資的 Skills 集中儲存在 GitHub 私有儲存庫，透過版本管理持續改善；實際載入與同步方式則取決於所用平台。 這其實就是企業很熟悉的 SOP（標準作業程序）。以前我們把工作經驗寫成 SOP，交給新人學習；現在可以把 SOP 整理成 Skills，交給 AI Agent 執行。想進一步整理自己的方法，可以參考從 Prompt 走向 Skill 工作流。 但也要注意：Skills 不保證 AI 永遠不會出錯，仍然需要測試、驗收與持續修正。 三、哪些工作交給 AI Agent，哪些應該寫成 Scripts？另一個值得深入研究的方向，是請 Bot 幫你寫程式，把重複性的工作流程自動化。 這個做法看似簡單，背後卻牽涉到 AI Agent 的成本與架構設計。 假設每天都要處理 100 封訂單郵件。如果讓 AI Agent 每次都打開信箱、閱讀郵件、擷取欄位、開啟試算表、填入資料，每個步驟都需要模型判斷，可能消耗大量 Tokens，也增加執行時間。 但換個方式呢？ 第一次先請 AI Agent 分析工作流程，幫忙寫好 Script。之後透過程式自動讀取授權範圍內的郵件、解析固定格式、整理訂單資料。只有遇到格式不一致、資訊缺漏或需要判斷的情況，才交給 AI Agent 處理。 這種設計有機會減少重複的模型呼叫，讓固定步驟更容易檢查；實際成本與穩定性仍要依郵件格式、錯誤率與維護需求驗證，不能只看 Token 數量。 我認為比較成熟的架構，可以這樣分工： 組成 負責什麼 訂單情境中的例子 AI Agent 思考、規劃與處理例外 判讀不規則來信、列出缺漏資訊 Scripts 固定且重複的執行 擷取固定欄位、去除重複紀錄、產出資料表 Skills 保存工作方法與驗收規則 定義訂單欄位、核對步驟與人工確認條件 自動化流程 決定何時啟動、如何交接 收到符合條件的郵件後啟動處理 三者互相搭配，再由自動化流程串起來，而不是什麼事情都丟給大型語言模型。 這也是為什麼我最近越來越重視 Codex、Cloudflare、GitHub 與各種自動化工具的整合。因為 AI 最有價值的地方，不只是幫你完成一次工作，而是幫你建立一套以後可以持續運作的流程。 四、如何用 Routines，讓 AI 在適當的時間主動工作？Routines 可以理解為例行任務。依 Grok Bot 官方工作指南，它可以依排程，或在支援的事件發生後啟動工作。 排程型：在指定時間執行例如每天早上八點，檢查授權的信箱、整理重要訊息、確認行事曆，並產出今日工作摘要。 事件觸發型：符合條件才開始工作例如當指定客戶寄來新郵件，AI 自動整理需求、更新允許修改的客戶紀錄，並準備回覆草稿。可用的事件來源與連接器，仍要以平台實際支援為準。 這兩種模式讓工作方式出現變化：以前我們要記得叫 AI 做事，現在可以讓系統在適當的時間，或特定事件發生時，自動開始工作。 但這裡也有一個很重要的管理問題：不是所有工作都需要每五分鐘檢查一次。觸發太頻繁，可能增加成本，也可能產生大量重複資訊。 所以我認為，設計 AI 自動化時，應該先思考三件事： 這件事情需要多即時？ 有沒有辦法先過濾不重要的事件？ 哪些結果需要人類確認才能執行？ 例如一般新聞整理，每天執行一次可能就夠了；重要客戶的緊急需求，則可能需要更即時的通知。只有出現值得處理的變化時再通知，也能減少干擾。 真正好的 AI Agent，是知道什麼事情值得做、什麼時候該做。 五、如何像培訓新同事一樣，讓 AI 正確完成任務？我們也可以用一個問題檢查自己的管理方式：如果今天聘請一位實習生，你會如何讓他熟悉工作，並確保他能正確完成任務？ 假設公司來了一位新員工，你會不會只跟他說「幫我把公司行銷做好」，然後就期待他自己把所有事情完成？應該不會吧！ 你至少會告訴他：公司是做什麼的、客戶是誰、有哪些工作流程、可以使用哪些工具、什麼事情需要主管核准，以及完成工作的標準是什麼。 但很多人在使用 AI Agent 時，卻只給它一句簡單的提示詞。發現結果不理想，就認為 AI 不夠聰明。問題可能不只在模型能力，也在於我們沒有提供足夠的工作背景與驗收標準。 這也是為什麼我認為，企業導入 AI Agent，不能只停留在提示詞教學，還需要建立： 工作角色與職責。 知識庫與 Skills。 工具使用權限。 標準作業流程。 任務驗收與錯誤回報機制。 以客戶回覆為例，「幫我處理客戶郵件」太籠統。比較清楚的交代是：整理來信需求、標示需要補問的資訊、依範本產出回覆草稿，完成後交給我審核，取得核准才寄出。 尤其涉及客戶資料、金流、對外發送訊息等工作，更需要明確的權限與審核制度。 AI Agent 可以自主執行工作，但自主不代表不需要管理。 六、下一階段的競爭，為什麼是 AI 管理能力？回頭看看這幾年的 AI 發展：最早大家比的是誰比較會寫 Prompt，後來比的是誰會使用更多 AI 工具，接著開始比誰會使用 AI Agent、誰會建立自動化流程。 但我認為，接下來真正拉開差距的，可能是另一種能力： 你能不能把自己的工作方法，轉換成一套 AI 可以持續執行、持續改善，而且能夠驗證成果的系統？ 例如我現在要製作一門 AI 課程。理想中的工作方式，是告訴 AI 幕僚長： 我要規劃一門六小時的 AI 實戰課程，對象是沒有技術背景的企業學員，希望每個人最後都能完成實際作品。 接著由 AI 研究員整理工具與案例、AI 教學設計角色規劃課程、AI 工程師建立互動式教學網站、AI 內容編輯準備招生文案。每個階段都要有清楚的輸入、交付物與交接條件。 最後由我檢查課程品質、調整教學策略、決定正式版本。這才是我期待的 AI 工作模式。 當然，這不代表目前每一套 AI Agent 平台都能完整做到，也不代表可以完全不需要人工介入。但這個方向值得持續實驗：我們正在從「使用 AI 工具」，走向「管理 AI 工作系統」。 從今天開始，先盤點這五個問題不要急著問自己還能建立多少個 AI Agent，先問問自己： 我每天有哪些工作，一直在重複做？ 哪些工作方法，可以整理成 Skills？ 哪些固定流程，可以直接寫成 Scripts？ 哪些事情，可以交給 AI 自動監控與處理？ 哪些決策，仍然需要我親自把關？ 當你開始用這樣的方式思考，就已經開始扮演一位 AI 團隊的管理者。 未來，真正有價值的可能不是一個人會操作十種 AI 工具，而是這個人能不能帶領一支由 AI Agent、Skills、Scripts 與自動化流程組成的團隊，完成過去需要好幾個人才能完成的工作。 你不需要擁有最多的 AI 員工，你需要的是一支真正能幫你完成工作的 AI 團隊。這才是我認為 AI AI 幫忙念出來。 其實現在的 TTS（Text-to-Speech，文字轉語音）已經進步很多。 至少可以分成三種能力。 1. 文字轉語音（TTS）輸入一段文字，選擇男聲或女聲，AI 就能生成配音。 例如： 「哈囉大家，我是米樂！今天要跟大家分享三個超實用的 AI 工具。」 這是最基本的應用，適合知識型短影音、教學動畫與新聞摘要。 2. 聲音複製（Voice Cloning）提供一段自己或已取得授權的聲音樣本，AI 就能模仿這個人的聲線，朗讀不同內容。 例如你錄製一段 15 秒的聲音，以後只要輸入文字，就能產生相似聲線的新配音。 這對 AI 網紅尤其重要。 因為觀眾可能不會記住每支影片的內容，但會逐漸熟悉角色的聲音。 如果每支影片的聲線都不同，就很難建立角色辨識度。 3. 聲音表演與情緒控制這是更進階的功能。 同一句話： 「真的假的？這也太厲害了吧！」
