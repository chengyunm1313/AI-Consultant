你是不是也有這種感覺？

Claude Code、Codex、Grok Bot 都訂了，剛開始玩得很興奮：幫我寫程式、整理文件、查資料，樣樣都能做。

但玩了幾天，反而卡在一個問題：

**接下來，到底要叫 AI Agent 幫我做什麼？**

很多人以為自己缺的是更厲害的 AI 模型，實際上可能缺的是「可以參考的工作案例」。

最近我看到一個很適合解決這個問題的免費網站：[Agent Use Cases](https://agentusecases.ai/)。

它把網路上大家實際交給 AI Agent 做的事情整理成案例庫，依工具、工作類型分類，還提供可以修改使用的提示詞。

對正在學 AI Agent 的人來說，比起再看一份工具排行榜，這類案例更容易幫你找到第一個值得動手的任務。

這篇文章就帶你實際操作：

**怎麼搜尋案例、判斷案例值不值得做、把提示詞改成自己的工作需求，以及如何驗收結果。**

## Agent Use Cases 是什麼？先認識案例庫的用途

網站：https://agentusecases.ai/

[Agent Use Cases](https://agentusecases.ai/about) 是由 Alex Finn 經營的 AI Agent 案例目錄，蒐集來自 X、Reddit、Hacker News 與其他公開網頁的使用經驗。依網站說明，使用者可以投稿，Alex Finn 會審核投稿，網站再核對來源、整理內容並附上原始連結。

截至 2026 年 11 月 5 日查核，網站顯示 1,852 個案例，數量會持續變動。

這不是另一套要你安裝的 AI 工具，而是一個**「別人用 AI Agent 做過什麼」的靈感與操作資料庫**。

它提供三種很好用的切入方式：

1. **依 Agent 找案例**：例如 Claude Code、Codex、Grok Bot、ChatGPT Agent、Meta Muse 或 n8n。
2. **依應用類別找案例**：例如工作與營運、銷售與行銷、影音內容、金流帳單、研究與知識管理。
3. **依具體任務找案例**：例如整理發票、尋找潛在客戶、製作影片、經營社群、清理信箱或產出每日簡報。

最值得注意的是，網站不只給你一句「AI 可以自動做某件事」。

進入單一案例後，通常還能看到：

- **What they did**：實際做了什麼
- **How it went**：執行結果如何
- **Worth knowing**：限制與注意事項
- **Try it yourself**：可以複製修改的提示詞
- **Read the original**：原始來源

換句話說，你可以從一個模糊的想法，一路找到別人做過的流程與可修改的指令。

## 如何用五個步驟找到能落地的 AI Agent 工作流？

### 步驟 1：先寫下你的工作問題

先不要問：「Codex 還可以做什麼？」

改問：

**「我每週有哪些工作重複做、很耗時間，而且能清楚判斷做對或做錯？」**

例如：

- 每週收到十幾張發票，要人工輸入試算表。
- 每次演講結束，都要花好幾個小時剪成短影音。
- 每天想寫粉專貼文，卻要花很多時間蒐集熱門話題。
- 想開發企業客戶，但不知道怎麼找名單與準備第一封信。

選案例的第一步是找到工作痛點，不是先決定用哪個模型。

### 步驟 2：在網站上選對搜尋入口

打開首頁後，可以直接用搜尋欄輸入英文關鍵字，或點選網站的分類。

下面幾個入口可以先收藏：

| 你想做的事 | 直接開啟的案例分類 |
| --- | --- |
| 研究 Codex 不寫程式還能做什麼 | [Codex 案例](https://agentusecases.ai/agents/codex) |
| 自動整理發票與帳務 | [發票與請款任務](https://agentusecases.ai/intents/chase-invoices) |
| 自動剪輯或製作影片 | [影片製作任務](https://agentusecases.ai/intents/make-a-video) |
| 搜尋企業潛在客戶 | [業務開發任務](https://agentusecases.ai/intents/find-sales-leads) |
| 自動產出社群貼文 | [社群貼文任務](https://agentusecases.ai/intents/write-social-posts) |
| 追蹤新案例 | [每日新增案例](https://agentusecases.ai/new) |

如果只是想找靈感，可以從熱門（Top）案例開始；如果想知道近期大家都在玩什麼，就看新增（New）。

網站也有 [RSS](https://agentusecases.ai/feed.xml) 與每日五個案例的電子報入口。

### 步驟 3：不要只看標題，要打開原始案例

假設看到「AI 自動整理發票」，請先檢查四件事：

1. **輸入是什麼？** PDF、照片、Email，還是雲端資料夾？
2. **Agent 真的做了什麼？** 只有擷取欄位，還是已經寫入 Google Sheets 並完成歸檔？
3. **成果有沒有數字或可驗證證據？** 還是只有作者一句「超好用」？
4. **需要哪些額外條件？** API Key、MCP、付費服務、瀏覽器登入或人工核准？

這一步很重要。

Agent Use Cases 整理的是公開回報的案例，**不代表每一則都由網站獨立重現與驗證**。

「Try it yourself」通常也是整理後的示範提示詞，不一定是原作者當時逐字使用的指令。

例如，本文下方的 n8n 發票案例有工作原型與示範影片，但案例頁明確說明，來源沒有提供辨識正確率或節省時間的數字。能完成示範，不等於已通過公司帳務的正式驗收。

所以，案例可以拿來找方向，成果仍要自己驗收。

### 步驟 4：複製提示詞，但一定要換成自己的需求

假設我們選擇這個案例：

[透過 n8n 擷取發票資料並整理到記帳試算表](https://agentusecases.ai/use-case/extract-invoice-data-and-file-it-into-a-bookkeeping-sheet)

原案例是將 PDF 或發票圖片送進工作流，讓 AI 擷取日期、商家、金額、稅率、分類等欄位，提供人工核對，再存回 Google Drive 與試算表。

如果你已經有 Codex 或 Claude Code，也可以先用較簡單的方式驗證核心需求，不必一開始就把 n8n、Google OAuth、Webhook 全部接好。原案例需要自行設定 OpenAI、Google Drive 與 Sheets 等憑證和識別資料；公開匯出的原型不能直接當成已配置好的服務。

下面是我改寫成適合台灣中小企業的實作提示詞：

**可以直接複製的提示詞：**

> **角色：** 你是我的行政助理，協助整理公司請款與發票資料。
>
> **任務：** 請讀取我指定資料夾內的 PDF 與發票圖片，擷取「發票日期、發票號碼、賣方名稱、統一編號、未稅金額、營業稅、含稅總金額」等欄位。
>
> **規則：**
>
> 1. 日期統一整理為 YYYY-MM-DD，遇到民國年請正確轉換。
> 2. 看不清楚的欄位請標記「待確認」，不可猜測。
> 3. 偵測可能重複的發票號碼，另外列出。
> 4. 先產生 CSV 與核對報告，保留原始檔案不變。
> 5. 在我確認前，不要移動、刪除、覆寫檔案，也不要寫入正式帳務系統。
>
> **驗收：** 先拿五張測試發票執行，逐欄比對原始影像，告訴我哪些欄位正確、哪些需要人工修正。確認通過後，再討論批次處理。

請注意：這是**改寫後的教學提示詞**，不是該網站原案例的逐字內容。

也不代表只貼上這段文字就一定能存取你的本機檔案。Agent 必須具備相應的檔案權限與辨識能力。

### 步驟 5：用 KPI 驗收，決定要不要自動化

很多人做到這一步就急著說「成功了」，但企業實際導入還要再問三個問題：

| 驗收項目 | 建議記錄方式 |
| --- | --- |
| 正確率 | 隨機抽查 20 張單據，比對各欄位的正確數量 |
| 節省時間 | 比較人工整理與 AI 輔助整理 20 張單據所需分鐘數 |
| 人工介入 | 記錄有多少張需要修正、重新辨識或補填 |

這裡的 20 張只是方便示範的測試樣本，不是網站宣稱的標準。

若要正式用於公司帳務，還要增加異常資料、重複發票、資料權限與備份的測試。

核心原則很簡單：

**先讓 AI 做出一個可核對的結果，再決定是否讓它批次執行、固定排程，甚至連接其他系統。**

## 除了發票整理，還有哪三種案例值得研究？

### 案例 A：把演講錄影自動剪成 Reels

[原始整理案例：Claude Code 自動剪輯演講影片](https://agentusecases.ai/use-case/edit-keynote-videos-with-motion-graphics-using-a-video-agent)

一位行銷工作者建立 Claude Code 影片代理，讀取演講影片、產生逐字稿、處理剪輯，接著用 FFmpeg 與 HyperFrames 製作動態視覺，輸出橫式及直式版本。

我認為這種案例特別適合講師、自媒體經營者與企業行銷團隊。

與其每次重頭剪片，不如把：

**逐字稿 → 精華片段 → 字幕 → 動態圖卡 → 多比例輸出**

變成固定工作流。

但影片的節奏、字幕可讀性、人物畫面與素材授權，仍需要最後檢查。

### 案例 B：每天自動整理熱門短影音選題

[原始整理案例：Grok Bot 追蹤社群熱門內容](https://agentusecases.ai/use-case/rank-viral-social-posts-and-send-top-picks-overnight)

這個案例利用 Grok Bot 搭配 Apify，蒐集 X、TikTok、Instagram 的內容，整理互動指標、挑出熱門貼文，再把精選結果送到 Telegram。

如果你正在經營 AI 網紅或品牌粉專，可以將它改成：

「每天追蹤指定領域的高互動影片，提供題材、開場鉤子與反轉方式。」

要注意，各平台能取得的數據不同，不能把不同來源的按讚、收藏與留言直接視為同一種指標；使用爬取服務也可能有額外費用或平台限制。

### 案例 C：讓 AI 幫忙建立企業客戶名單

[原始整理案例：Grok Bot 業務名單與開發流程](https://agentusecases.ai/use-case/build-lead-lists-and-multichannel-outbound-sequences)

案例中，Grok Bot 搭配 Leadsforge 與 Salesforge API，根據企業網站與理想客戶輪廓（ICP）整理潛在客戶，分類適合程度，並草擬 Email 與 LinkedIn 聯繫流程，經作者審閱核准後才啟動。

原作者回報有 38% 的回覆率，但這是個別案例成果，不能直接當成一般企業都能達到的預期。

如果換成台灣的企業 AI 教育訓練市場，可以先讓 Agent 蒐集公開的產業與公司資料、分析可能需求、整理建議拜訪名單，最後由業務人員確認聯絡資料與開發內容。

我會把「自動寄出」留在後面階段，先做好名單正確性與內容品質。

## 使用 AI Agent 案例時，最常見的三個錯誤

**錯誤一：看到精彩案例，就以為貼上提示詞一定能重現。**

提示詞只是一部分。

工作流能否執行，還取決於工具權限、API、資料來源、檔案格式、第三方服務是否開放自動操作等條件。

**錯誤二：把作者自述的成功數字，當作保證成果。**

省下多少時間、賺多少錢、拿到多少曝光，必須回頭看原始來源與測試條件。

尤其涉及金錢交易、個人資料與帳戶操作時，建議保留人工確認。

**錯誤三：一開始就追求全自動。**

更穩定的做法通常是三個階段：

1. 先產出草稿供人審核。
2. 再進一步自動處理可逆的步驟。
3. 最後才將已驗證的流程排程化。

## 如何開始？先挑一件每週都要做的工作

如果你手上已經有 Claude Code、Codex 或 Grok Bot，我的建議是：

**先別急著再訂新的 AI 工具。**

挑一件你每週都要做、重複性高、資料容易取得、結果能檢查的工作。

到 Agent Use Cases 找兩三個相近案例，看看別人如何處理，再把提示詞改成自己的流程。

第一次不必全自動，也不必一口氣串十個服務。

只要能把原本 30 分鐘的工作縮短，而且結果可驗證，就已經很有價值。

我一直認為，AI Agent 的真正差異不在於「它能回答多少問題」，而在於：

**你能不能把一件工作清楚交辦出去，讓它實際完成，還能檢查品質。**

現在缺的未必是更強的模型，而是值得讓 AI 接手的工作清單。

下次不知道要叫 AI Agent 做什麼，就打開這個網站，找一個案例，從小規模測試開始。

或許你需要的下一個自動化工作流，就藏在別人的使用經驗裡。

## 常見問答 (FAQ)

### Q1：Agent Use Cases 免費嗎？看案例就能直接執行嗎？

本文查核時，案例目錄與案例頁可公開瀏覽。網站提供案例說明、原始來源與可修改的示範提示詞；真正執行時，仍需要自己的 Agent、檔案權限及對應工具。AI 訂閱、API、爬取服務或其他整合可能另有費用，不能把免費瀏覽案例當成整套工作流免費。

### Q2：一定要先安裝 n8n 或 MCP，才能使用這些案例嗎？

不一定。先看案例的輸入、輸出與工具需求，再用手上已有的 Agent 測試核心任務。例如發票整理可先用五張測試影像產生 CSV 與核對報告，確認品質後，再決定是否串接 n8n、Google Drive、Sheets 或排程。

### Q3：網站上的成果數字與提示詞，可以保證重現嗎？

不能。個案的回覆率、節省時間與執行成果，取決於資料、工具版本、權限及測試條件；示範提示詞也不一定是原作者逐字使用的指令。應先讀原始來源，再以自己的小樣本檢查正確率、處理時間與人工修正量，通過後才擴大執行。
