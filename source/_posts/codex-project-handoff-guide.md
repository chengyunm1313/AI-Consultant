昨天才和 AI 討論好網站要做什麼，今天開啟新對話，它卻又問：「你想做什麼網站？」

或者，原本用 Claude Code 寫到一半，想換 Codex 接手，卻得把需求、決策和目前進度重新說一次。更麻煩的是，明明已經說過某個功能不要做，換個對話，AI 又把它加回來。

對剛開始學 AI Coding 的人來說，有個實用的習慣：**把重要的專案資訊寫進檔案，讓每次工作的 AI 都能重新讀取。**

這篇不教複雜語法，也不需要先安裝外掛。我們會用一個簡單的網站練習，建立三份 Markdown 文件，並準備「初始化、開工、收工」提示詞，讓新對話有機會從上次的進度繼續。

## 三個 Markdown 檔案各自負責什麼？

這個做法參考三師爸 Sense Bar 在「AI Agent 基本功」EP06 分享的跨電腦專案管理流程，再加上一份 project.md，把長期需求和每天的工作進度分開。

| 檔案 | 可以把它想成 | 記錄內容 |
|---|---|---|
| project.md | 專案企劃書 | 專案目標、使用者、已確認需求、暫不處理的項目、重要決策和驗收標準 |
| AGENTS.md | AI 工作守則 | AI 在這個專案裡要遵守的規則，以及需要讀取哪些文件 |
| handoff.md | 工作交接簿 | 目前進度、已驗證與未驗證項目、問題、下一步和最後更新時間 |

三份檔案都是純文字 Markdown，可以用文字編輯器打開。你不必先學會 Markdown；用一般文字和標題整理內容就能開始。

其中，AGENTS.md 是 Codex 支援的指示檔，Codex 會依照檔案所在位置讀取適用的專案指示。project.md 和 handoff.md 則是我們自行約定的檔名；若希望 AI 使用它們，請在提示詞中要求讀取，或在 AGENTS.md 裡清楚指示何時讀取。OpenAI 官方文件也說明了 [Codex 如何發現 AGENTS.md](https://developers.openai.com/codex/guides/agents-md)。

## 第一次實作：先建立專案文件

我們用「製作一個 AI 入門課程介紹網站」當作練習。先在 Finder 建立一個資料夾，例如 my-first-ai-website，接著在 ChatGPT 桌面版中選擇這個資料夾作為工作位置，並在新對話中選擇 Codex。介面名稱可能隨版本調整；官方 [Codex Quickstart](https://developers.openai.com/codex/quickstart) 有目前的桌面版入門說明。

第一步先不要叫 AI 寫網站，請它建立需求和交接文件。可以貼上這段提示詞：

**提示詞 ①｜初始化我的第一個專案**

~~~text
你現在是我的 Codex 入門教練。

我完全不懂程式設計，請用台灣繁體中文、
新手能理解的方式協助我。

我要建立一個「AI 入門課程介紹網站」。

目標：
讓一般人可以透過網站了解課程內容，
包含課程介紹、學習特色、適合對象、
常見問題及聯絡方式。

請先不要製作網站程式。

第一步，請確認目前專案的工作目錄。

第二步，在專案根目錄建立三份 Markdown 文件：

1. project.md
記錄專案目標、目標使用者、
確定要做的功能、暫時不做的功能、
重要決策及驗收標準。

2. AGENTS.md
記錄 AI 工作規則。
要求 AI 在接續任務時，按需要讀取
project.md 和 handoff.md。
不得擅自增加功能、改變已確認需求，
或把尚未完成的工作說成已完成。

3. handoff.md
記錄目前進度、完成事項、驗證狀態、
待辦事項及下一步工作。

第三步，說明這三份文件各自的用途。

要求：
- 不要安裝任何套件
- 不要部署網站
- 不要推送到 GitHub
- 不要修改專案資料夾以外的檔案
- 如果已有同名文件，先檢查，不要直接覆蓋
- 完成後確認三份檔案確實存在
~~~

這段提示詞也要求 AI 確認工作目錄、檢查同名文件，並在完成後確認檔案確實存在。AI 在聊天裡說「完成」不代表檔案已經寫入；可以回到 Finder，確認資料夾裡看得到：

~~~text
my-first-ai-website/
├── AGENTS.md
├── project.md
└── handoff.md
~~~

## 文件準備好後，再請 AI 製作網站

三份文件建立後，請 AI 先讀取規格，再依規格動工。這能讓已確認的需求和限制比較容易帶進下一步。

**提示詞 ②｜按照專案規格製作網站**

~~~text
請先讀取 project.md、AGENTS.md
和 handoff.md，確認目前的專案目標與限制。

接著開始製作第一版網站。

需求：
1. 使用 HTML、CSS 和必要的 JavaScript
2. 暫時不使用資料庫或後端服務
3. 網站要有課程介紹、課程特色、
   適合對象、常見問題、聯絡方式
4. 使用繁體中文
5. 電腦與手機都要能正常閱讀
6. 版面簡潔、專業，適合 AI 入門課程
7. 聯絡功能先使用示範內容，
   不要假裝已經完成正式報名或付款系統

完成後：
- 確認程式檔案已建立
- 檢查是否有明顯錯誤
- 告訴我如何在 Mac 上開啟網站
- 區分已驗證與尚未驗證的功能
- 用新手能理解的方式解釋結果
~~~

網站完成後，可以依照 AI 提供的方法預覽，再把瀏覽器視窗縮小，檢查手機版是否容易閱讀。如果發現 FAQ 字太小，可以具體要求：「手機版 FAQ 文字太小，請加大字體、調整行距，但不要修改其他區塊。」

用自然語言描述想看到的結果，是 AI Coding 對初學者很有幫助的地方；仍要親自檢查畫面和功能，不能只看 AI 的完成摘要。

## 每天結束前更新交接簿

準備休息時，請 AI 根據專案檔案和實際成果更新 handoff.md。交接內容要分清楚哪些已完成、哪些真的驗證過，以及哪些還沒檢查。

**提示詞 ③｜收工，保存交接進度**

~~~text
今天先做到這裡，請幫我收工。

請檢查目前專案檔案與實際工作成果。

更新 handoff.md，包含：
- 這次完成了什麼
- 哪些功能已驗證
- 哪些功能尚未驗證
- 有哪些問題或阻礙
- 下次建議先做的三件事
- 最後更新時間

如果本次沒有改變已確認的需求，
就不要修改 project.md。

如果有重要需求變更，
先列出差異供我確認，不要自行定案。

請不要刪除檔案、部署網站，
也不要自動推送到 GitHub。

最後告訴我文件實際更新了哪些內容。
~~~

例如，「表單介面已經寫好」不代表「報名資料已成功送出」。這兩種狀態分開記錄，下一次接手時才不會把未驗證的功能誤認為完成。

## 隔天開新對話時，先開工再修改

隔天重新開啟同一個專案資料夾，開始新對話。先請 Codex 讀取三份文件，並檢查專案目前的 Git 狀態，再決定今天要做什麼。

**提示詞 ④｜開工，接續昨天的工作**

~~~text
今天要繼續這個專案，請幫我開工。

先確認目前工作目錄。

讀取：
1. AGENTS.md
2. project.md
3. handoff.md

如果專案有使用 Git，
也請檢查目前版本與未提交的變更。

請先不要修改程式。

告訴我：
- 這是什麼專案
- 已經完成了什麼
- 哪些地方還沒驗證
- 上次停在哪裡
- 今天最適合先做哪三件事

請不要重新製作已完成的功能。
~~~

這份交接不是昨天聊天紀錄的摘要，而是要求 AI 對照專案目前的檔案與變更。若交接文件已經過期，或實際程式和文件不一致，就要先核對再動工。

## 想自動化開工和收工時，再了解 Skill

每次複製長提示詞可能有點麻煩。熟悉基本流程後，可以再研究把常用指示整理成 Skill，減少重複輸入。

三師爸 Sense Bar 開源的 [cross-device-agent-skills](https://github.com/mathruffian-dot/cross-device-agent-skills) 提供三個流程：project-init（初始化專案）、startup（開工）和 shutdown（收工）。它也介紹 GitHub 和 Obsidian 等延伸整合，實際效果會依安裝、設定和可用工具而不同。

要先看清楚 Skill 會讀寫哪些檔案、需要哪些權限，以及是否會操作 Git。該專案 README 說明 shutdown 流程可能執行 git commit 和 git push；如果你不希望 AI 自動提交或推送，就要在使用前檢視流程並調整規則。想延伸了解 Skill 與 Plugin 的差異，可以參考站內的 [Codex Skill 與 Plugin 指南](/posts/codex-skills-vs-plugins/)。

## GitHub 和 Google Drive 要一開始就設定嗎？

剛開始練習時，可以先只在本機完成三件事：

1. Codex 在正確的資料夾建立了專案文件。
2. 新對話能照指示讀取前一次的進度。
3. 收工時能根據實際成果更新交接簿。

熟悉之後再學 GitHub。GitHub 能保存版本歷史，也可讓不同電腦取得專案；但「本機 commit」只代表建立了一筆本機版本紀錄，還要成功 push 才會送到遠端。

Google Drive 桌面版可以同步一般檔案，但若多台電腦同時修改同一個專案，可能發生同步衝突。跨裝置工作前，先了解雲端同步和 Git 的使用方式；不要把「檔案在雲端資料夾」當成「版本備份和同步都已驗證」。

## 已經寫一半的專案，也能補上交接文件嗎？

可以。先請 AI 檢查目前專案和既有文件，再根據實際內容整理，不必從頭重做。遇到資訊不足的地方，標記「待確認」，不要猜測，也不要覆蓋原有設定。

**提示詞 ⑤｜替舊專案補上交接機制**

~~~text
我已經有一個正在開發中的專案。

請先檢查現有的資料夾、
程式檔案和專案文件。

不要重新製作網站，
也不要覆蓋原有設定。

請根據實際內容，協助我整理：
- project.md：專案目標、需求、限制、
  已確認決策及驗收標準
- AGENTS.md：AI 工作守則和文件入口
- handoff.md：目前進度、驗證狀態與下一步

如果已經存在相關文件，請優先整合，
避免產生互相矛盾的規則。

請嚴格區分：
使用者已確認的要求、
AI 自己提出的建議、
實際完成的功能、
尚未驗證的工作。

不確定的事項請標記「待確認」，
不要自行猜測。

完成後提供文件摘要與差異，
不要擅自變更功能或部署網站。
~~~

## 專案文件讓接手更清楚，仍要核對實際成果

project.md、AGENTS.md 和 handoff.md 不會自動讓 AI 永遠記得所有事情。它們的用途是把重要需求、工作規則和目前進度放在容易找到的位置，讓每次接手時有一份可查閱的依據。

文件可能過期，AI 也可能漏讀；開始修改前仍要對照程式、版本控制狀態和實際驗收結果。對 AI Coding 新手而言，先學會保存需求、標示驗證狀態和更新交接內容，往往比多背幾段提示詞更能讓專案順利延續。

## 常見問答 (FAQ)

### Q1：project.md 和 handoff.md 會被 Codex 自動讀取嗎？

預設情況下，Codex 會依規則發現適用的 AGENTS.md。project.md 和 handoff.md 是自訂檔名，應在提示詞中明確要求讀取，或透過 AGENTS.md 指示 Codex 何時讀取。

### Q2：不會寫程式，也能使用這三份文件嗎？

可以。你可以用一般文字描述目標、限制和進度，再請 Codex 協助整理文件。仍要親自確認需求和驗收結果是否正確。

### Q3：建立 handoff.md 就等於已經備份專案嗎？

不是。handoff.md 只是記錄工作的文字檔。若要保存程式版本或在不同裝置取得專案，還需要設定 Git、遠端儲存或同步工具，並確認相關操作確實成功。

### Q4：已經開發一半，還能開始使用嗎？

可以。先檢查現有檔案和文件，再整理專案目標與進度；不確定的內容標記待確認，避免把建議誤寫成已確認需求。

### Q5：交接文件可以完全避免 AI 重做或誤解需求嗎？

不能保證。文件能降低重新交代的成本，但仍需要定期更新，並在每次工作開始時對照實際檔案、程式狀態和驗收結果。
