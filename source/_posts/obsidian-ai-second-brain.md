## 一、什麼是 Obsidian？為什麼適合當第二大腦？

[Obsidian](https://obsidian.md) 是一套以 Markdown 為基礎的知識管理軟體。

它和一般雲端筆記工具最大的不同，就是採用「本機優先」（Local-first）的設計理念。你的筆記主要以一般檔案形式儲存在自己的電腦上，而不是只能透過某個雲端服務存取。

這帶來幾個優點：

- **資料自主權**：Markdown 檔案可以自行備份、搬移，不必依賴單一平台才能閱讀。
- **雙向連結**：不同筆記可以互相連結，逐漸形成自己的知識網路。
- **跨平台使用**：支援 Windows、macOS、Linux、iOS 與 Android。
- **高度擴充**：可以透過外掛增加資料管理、搜尋、自動化等功能。
- **適合 AI Agent**：Markdown 是文字格式，取得檔案存取權限的 AI 可以讀取、分析與編輯。

Obsidian 本身可以免費使用，官方另外提供付費的同步及發布服務；實際方案請以 [官方價格頁](https://obsidian.md/pricing) 為準。

對我來說，最後一點特別重要。因為現在使用 AI Agent，最大的問題之一，就是不同 AI 工具的知識不容易共享。

如果把知識集中儲存在 Markdown 檔案裡，未來不論使用 Codex、Claude Code，還是其他支援檔案存取的 AI Agent，都有機會使用同一套知識。

## 二、如何免費下載 Obsidian 執行長的第二大腦範本？

GitHub 專案：[kepano/kepano-obsidian](https://github.com/kepano/kepano-obsidian)。

這是 Steph Ango 公開的個人 Obsidian 使用範本。裡面包含筆記架構、範例、範本及相關設定；原作者也強調，可以挑選適合自己的部分調整，不必整套照搬。

### Step 1：下載 Obsidian

前往 [Obsidian 官方網站](https://obsidian.md)，依照自己的作業系統下載並安裝。

### Step 2：下載第二大腦範本

開啟 [GitHub 專案頁](https://github.com/kepano/kepano-obsidian)，點選綠色的 **Code** 按鈕，再選擇 **Download ZIP**。

下載完成後，將 ZIP 檔案解壓縮。

### Step 3：使用 Obsidian 開啟範本

開啟 Obsidian，在儲存庫管理畫面選擇「開啟資料夾作為儲存庫」（Open folder as vault），接著選擇剛剛解壓縮的資料夾。

完成後，就可以開始研究這套第二大腦。

第一次開啟下載的儲存庫時，Obsidian 可能會詢問是否信任相關外掛。建議先檢查設定與外掛內容，再決定是否啟用。

## 三、最值得學習的四個知識管理方法

以下四個觀念，參考原作者的 [How I use Obsidian](https://stephango.com/vault)；程式碼與 AI 工具案例則是本文的延伸示範。

### 1. 不要建立太多資料夾，用 Properties 彈性分類

我們平常整理檔案，最直覺的方法就是分類。例如：

```text
AI 工具 → 影片生成 → Seedance
AI 工具 → 程式開發 → Codex
AI 工具 → 自動化 → AI Agent
```

問題是，一份資料可能同時屬於好幾個分類。例如一篇介紹 Claude Code 自動剪輯影片的文章，到底應該放在「AI 工具」、「影片製作」，還是「程式開發」？

分類越細，反而越容易找不到。

kepano 的方法偏向扁平化管理，讓大部分筆記不需要被限制在層層資料夾中。需要分類時，可以使用筆記屬性（Properties）。

例如，在 Markdown 筆記最上方放入：

```yaml
---
title: Claude Code AI 自動剪輯
categories:
  - AI Agent
  - 影片製作
  - 自動化
status: researching
---
```

同一篇筆記可以有多個分類，這樣就不用一直煩惱資料到底應該放在哪個資料夾。

### 2. 用雙向連結建立知識網路

Obsidian 最有代表性的功能，就是雙向連結。假設今天寫了一篇「Claude Code 自動剪輯影片」，內容可以這樣寫：

```markdown
# Claude Code 自動剪輯影片

使用 [[Claude Code]] 建立影片剪輯流程。
搭配 [[FFmpeg]] 處理影片。
使用 [[Whisper]] 產生字幕。
最後透過 [[AI Agent]] 自動完成工作。
```

雙中括號 `[[ ]]` 是 Obsidian 的內部連結語法。即使目標筆記還沒有建立，也可以先加上連結；未來建立對應筆記後，就能自然串接起來。

久而久之，你會得到一張知識網路。例如：

```text
Claude Code → AI Agent → 自動剪輯 → FFmpeg → 短影音行銷
```

這比單純把文章放在資料夾裡，更容易發現不同知識之間的關係。

### 3. 每日筆記可以作為時間索引

一般人聽到 Daily Notes，可能會想到每天寫日記。但 kepano 的做法更精簡：**他的每日筆記不寫內容，只讓其他筆記連回對應日期。**

重點是讓當天發生的事情、研究過的工具、參與的專案，都能連回這一天。

如果你希望打開日期頁就看到工作摘要，也可以延伸成下面的格式。這是本文的調整版，不是原作者每日筆記的原樣：

```markdown
# 2026-11-11

## 今日研究

- [[Obsidian]]
- [[kepano-obsidian]]
- [[AI Agent 第二大腦]]

## 今日工作

- [[AI 行政自動化課程]]
- [[AI 短影音工作流]]
```

以後想知道某一天研究了什麼、做了什麼事情，就可以透過每日筆記回顧。如果搭配 AI Agent，甚至可以讓 AI 每天自動整理工作紀錄，再由自己確認。

### 4. 用 1～7 分建立自己的評價系統

這個做法我也很喜歡。不論是書籍、電影、餐廳或其他值得評價的項目，都可以使用七分制。

為什麼不是十分制？因為十分制有時候太細，很難區分 7 分和 8 分到底差在哪裡。七分制相對簡潔，也保留區分好體驗的空間。

例如，我們也可以把這個方法應用到 AI 工具評測：

| 分數 | 個人評價標準 |
| --- | --- |
| 7 | 極力推薦，值得長期使用 |
| 6 | 非常好用 |
| 5 | 好用，值得保留 |
| 4 | 普通，特定情境可用 |
| 3 | 有明顯限制 |
| 2 | 不太推薦 |
| 1 | 不符合需求 |

**這張表是我建議的 AI 工具評價範例，不是原作者的正式評分定義。**

如果長期累積這些評價，AI Agent 就可以根據你的實際使用經驗，協助比較工具，而不是每次都重新上網搜尋別人的排行榜。

這樣回答就不只是憑印象，而是有實際紀錄可以參考。

## 五、進階玩法：Obsidian × AI Agent，打造真正的第二大腦

前面介紹的，其實還是傳統的知識管理方法。但到了 AI Agent 時代，我認為可以再往前走一步。

以前是人類自己整理知識，現在可以讓 AI 協助整理，而人類專心判斷哪些知識真正有價值。

例如，我每天會接觸很多資料：

- GitHub 開源工具
- AI 模型更新
- AI Agent 技術文章
- 課程教材
- AI 影片製作工作流
- 客戶專案與研究紀錄

如果每次都要自己手動分類、摘要、建立連結，長期下來一定很花時間。因此，我會考慮建立這樣的工作流程。

### Step 1：建立共用的 Markdown 知識庫

先用 Obsidian 建立知識庫，除了原本的筆記結構，再增加適合 AI 工作流的專案、研究與範本管理。例如：

```text
AI-Second-Brain/
├── Notes/
├── Projects/
├── Daily/
├── Clippings/
├── References/
├── Templates/
├── Reviews/
└── Skills/
```

這是延伸設計，不是 kepano 範本的原始結構。資料夾只保留明確用途，不必再往下建立多層分類。

### Step 2：讓 AI Agent 自動整理研究資料

假設今天看到一個新的 GitHub 專案，只要把網址交給 AI Agent：

> 幫我研究這個 GitHub 專案，整理功能、技術架構、安裝方法、授權與適合的應用情境，並存入 Obsidian 知識庫。

取得必要存取權限後，AI 就可以依照固定格式產生 Markdown 筆記。例如，以 [OpenMontage](https://github.com/calesthio/OpenMontage) 作為待研究項目，先建立資料欄位：

```yaml
---
title: OpenMontage
type: github-project
categories:
  - AI 影片製作
  - 開源工具
rating:
status: researching
source: https://github.com/calesthio/OpenMontage
---
```

這段只是筆記格式示例，功能與授權仍需研究來源後填入。接著整理：

- 專案介紹
- 核心功能
- 技術架構
- 安裝方式
- 使用情境
- 授權限制
- 相關筆記

研究確認有關聯後，還可以加入內部連結：

```markdown
- [[AI 影片製作]]
- [[Claude Code]]
- [[自動剪輯工作流]]
```

這樣每次研究新工具，就能逐漸擴充自己的知識網路。

### Step 3：讓多個 AI Agent 使用同一套知識

這是我最想實驗的部分。目前很多人同時使用 ChatGPT、Claude Code、Codex，甚至還有自己的 AI 助理，但每個 AI 的上下文與記憶往往不同。

如果能讓它們共同使用同一個 Markdown 知識庫，就能減少重複說明背景資料的時間。例如，我會考慮這樣分工：

| 工具 | 預計負責的工作 |
| --- | --- |
| Codex | 整理 GitHub 專案、批次更新筆記與建立自動化程式 |
| Claude Code | 研究技術、撰寫教學文章、分析不同工具的優缺點 |
| Dot 個人助理 | 每天的工作摘要、研究追蹤及定期回顧 |

這是我的分工構想，實際能力與整合方式會隨版本及方案變動。

不過要注意，這是一個可以實作的整合方向，**不代表所有 AI Agent 都能原生直接存取 Obsidian**。

本機工具可以透過檔案系統讀寫 Markdown；雲端 Agent 則可能需要 Git、雲端儲存或其他整合介面。同步或傳送內容前，也要先確認哪些筆記適合交給該服務處理。

而且多個 Agent 同時修改同一份筆記，還需要處理同步衝突與權限管理。比較穩定的方式，是先建立一個主要寫入流程，其他 Agent 以讀取為主，重要修改再經過確認。

### Step 4：讓 AI 定期回顧舊知識

這個功能我認為很有價值。kepano 會隨機翻閱舊筆記，重新整理內容、補上連結，而且刻意保留人工整理的過程。

知識管理不只是在整理資料，也是在重新閱讀時產生新的想法。所以 AI 不一定要取代這個步驟。

我們可以讓 AI 每週推薦五則值得重新閱讀的筆記，並說明：

> 這篇三個月前研究的工具，現在可能可以搭配最近的新技術。

或者：

> 你之前研究的影片自動剪輯流程，和這週的新模型有關聯，值得重新測試。

最後由人類決定要不要更新。這樣既能享受自動化的便利，也能保留知識整理最重要的思考過程。

## 六、我會怎麼開始？先做最小可行版本

如果你是第一次使用 Obsidian，我不建議一開始就安裝十幾個外掛，或設計非常複雜的知識管理系統。反而可以先從三件事開始：

| 時間 | 先完成的事情 |
| --- | --- |
| 第一週：建立基本知識庫 | 下載 kepano 範本，熟悉 Markdown、Properties、雙向連結和每日筆記。 |
| 第二週：開始累積真正會用到的資料 | 每天放入三到五則筆記，例如 GitHub 專案、AI 工具研究或工作心得；先確保資料有來源、有分類、有基本連結。 |
| 第三週：導入 AI Agent | 讓 Codex 或 Claude Code 協助整理新筆記，建立固定格式，並測試自動產生每日摘要。 |

等這套流程穩定後，再考慮跨裝置同步、多 Agent 協作，以及更進階的自動化。

## 七、我的心得：第二大腦的重點不是收藏，而是重新使用

以前我們使用筆記軟體，常常把重點放在「怎麼儲存」。看到好文章，收藏；看到好工具，收藏；看到有趣的 GitHub 專案，還是收藏。

最後資料越來越多，卻沒有真正派上用場。但我認為 AI Agent 時代，第二大腦應該有三個能力：

1. **能持續累積知識。**
2. **能找到不同知識之間的關聯。**
3. **能在真正需要的時候，把知識重新拿出來使用。**

例如，下次要準備 AI 影音課程，AI 不只搜尋網路上的最新工具，還能找出自己過去研究過的模型、實測結果、工作流和教學心得。

這些長期累積的個人經驗，才是真正有價值的知識資產。

Obsidian 提供的是儲存與連結知識的基礎；AI Agent 則有機會讓這些知識變得更容易整理、搜尋和運用。

我認為未來真正厲害的，不是你收藏了多少 AI 工具，而是你的 AI Agent 能不能把你累積的知識，持續轉換成新的成果。

**這才是我想打造的 AI 第二大腦。**

## 常見問答 (FAQ)

### Q1：Obsidian 與 kepano 的第二大腦範本需要付費嗎？

Obsidian 本身可免費使用，kepano-obsidian 範本也可從 GitHub 免費下載。官方的 Obsidian Sync 與 Publish 是另外提供的付費服務，並不是開始使用本機筆記的必要條件。方案以官方價格頁為準。

### Q2：Codex、Claude Code 或其他 AI Agent 能直接使用 Obsidian 筆記嗎？

支援本機檔案存取、且已取得權限的 Agent，可以讀寫儲存庫裡的 Markdown 檔案。雲端 Agent 可能需要額外整合，不能假設所有工具都原生支援 Obsidian。多個 Agent 協作時，建議先安排單一主要寫入流程，避免同時修改造成衝突。

### Q3：新手一定要完整照搬 kepano 的資料夾與每日筆記方法嗎？

不需要。可以先下載範本，練習 Properties、內部連結與日期索引，再依自己的工作調整。kepano 的每日筆記本身不寫內容；本文示範的每日摘要、AI 專案資料夾與工具評分表，都是可自行選用的延伸設計。
