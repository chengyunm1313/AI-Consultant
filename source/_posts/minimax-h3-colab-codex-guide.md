想用 AI 生成會說話的數位人影片、AI 網紅短劇，卻發現自己的電腦沒有 NVIDIA 顯示卡？

最近在 GitHub 發現兩個很有意思的開源專案：

- [minimax-h3-colab](https://github.com/dseditor/minimax-h3-colab)
- [h3-colab-skill](https://github.com/dseditor/h3-colab-skill)

這兩個專案都由開發者 dseditor 製作，而且都能透過 Google Colab 的 GPU 執行 MiniMax H3 影片生成模型。

乍看之下，似乎只是兩種不同的安裝方式。

但仔細研究後，我發現它們代表的是兩種完全不同的 AI 工作模式。

**第一個專案，是讓我們操作 AI 生成工具。**

**第二個專案，是讓 AI Agent 幫我們操作 AI 生成工具。**

差別看似不大，卻會直接影響未來 AI 影音製作的自動化程度。

## 一、MiniMax H3 是什麼？

MiniMax H3 是一套可以結合視覺與音訊條件生成影片的 AI 模型。

除了基本的影片生成，也能依照不同工作流，實現以下功能：

- 文字生成有聲影片
- 人物照片生成會說話的影片
- 參考圖片、影片、音訊生成新影片
- 利用首幀與尾幀控制影片
- 延伸既有影片
- 搭配額外的 P-H3-Image 元件進行圖片生成及編輯
- 透過特定工作流生成 TTS 語音

不過，H3 對硬體的要求不低，想在一般個人電腦上執行並不容易。

這時候，Google Colab 就派上用場了。

你可以利用 Colab 提供的雲端 GPU 執行 H3，不必購買高階 NVIDIA 顯示卡。

而今天介紹的兩個專案，就是利用這個方式降低使用門檻。

## 二、如何選擇 Colab 手動操作與 Codex 自動化？

| 比較項目 | minimax-h3-colab | h3-colab-skill |
|---|---|---|
| 專案定位 | Colab 影片生成平台 | AI Agent 自動化 Skill |
| 操作方式 | 使用者手動操作 | 自然語言交辦 AI |
| 執行引擎 | H3 + ComfyUI／Toybox | 使用 H3 Toybox 引擎 |
| 文字生成影片 | 支援 | 支援 |
| 參考圖片生成影片 | 支援 | 支援 |
| 頭尾幀生成 | 支援 | 支援 |
| 影片延伸 | 支援 | 支援 |
| 圖片生成 | 選用 | 選用 |
| 獨立 TTS 任務 | 非主要功能 | 支援 |
| 多工作批次生成 | 以網頁操作為主，Toybox 另有短片 Agent | 以工作清單串接多種任務 |
| 自動啟動 Colab | 不支援完整自動啟動 | 支援 |
| 自動下載成品 | 部分筆記本支援 | 支援 |
| 自動關閉 GPU | 主要由使用者管理 | 支援 |
| 適合對象 | 初學者、教學 | Codex、Claude Code 使用者 |

簡單來說：

如果你只是偶爾生成一兩支影片，第一個專案就很好用。

但如果你需要反覆生成分鏡圖、多支影片與配音，第二個專案的批次工作清單會更有吸引力。剪輯仍須交給其他工具。

兩者並非「有無 Agent」的絕對區分：第一個專案的 Toybox 文件也列有 Gemini 短片 Agent。本文主要比較使用者操作網頁，以及由桌面 Agent 管理 Colab、提交批次與收回檔案的差異。

值得注意的是，第一個專案本身也包含一個基礎的數位人 Skill。

不過，該 Skill 需要你先手動啟動 Colab，再把連線網址交給 AI。

第二個專案則更進一步，讓 AI 負責整個 Colab 執行流程。

## 三、教學一：使用 minimax-h3-colab

這個專案比較適合第一次接觸 MiniMax H3 的使用者。

作者準備了三套 Google Colab 筆記本。

### 1. H3 Basic ComfyUI

這是最基礎的版本。

它會在 Google Colab 中安裝 ComfyUI 與 H3 模型，讓你自行操作工作流節點。

適合：

- 已經熟悉 ComfyUI 的使用者
- 想研究 H3 工作流的人
- 想修改模型參數及節點組合的開發者

### 2. H3 Digital Human

這個版本專門用來生成數位人影片。

你可以上傳一張人物照片，再提供提示詞。

例如：

「讓照片中的台灣女生對鏡頭說：大家好，我是米樂，今天帶大家一起探索台北最好吃的咖啡廳。」

接著設定影片長度、解析度和 Seed，就能開始生成。

這個版本特別適合：

- AI 網紅口播
- 數位人介紹影片
- 虛擬主播
- 角色對白實驗

### 3. H3 Toybox

**想先體驗網頁操作，可從這個版本開始。**

Toybox 是作者製作的網頁操作介面。

你不用學會 ComfyUI 的節點，也能直接操作多種 H3 影片生成模式。

目前包含：

- 參考生成
- 頭尾幀生成
- 純文字生成
- 影片延伸
- 提示詞改寫
- 選用的圖片生成及編輯功能

此外，Toybox 還可以設定不同的提示詞改寫來源，例如本地模型、Gemini 或 OpenAI 相容 API。

### 實際操作步驟

**Step 1：開啟 Colab**

直接點選：

[開啟 H3 Toybox Google Colab](https://colab.research.google.com/github/dseditor/minimax-h3-colab/blob/main/H3_Toybox.ipynb)

**Step 2：設定 GPU**

進入 Colab 後，選擇：

「執行階段 → 變更執行階段類型」

將 GPU 設為 L4。專案文件以 Google AI Pro 與可用 Colab 運算單元為前置條件，並指出這套 int8 工作流不適用 T4。實際方案資格與 GPU 配額，請先在自己的 Colab 帳號確認。

**Step 3：執行筆記本**

Toybox 筆記本主要執行三格：

1. 安裝 ComfyUI 與必要元件。
2. 下載 H3 模型。
3. 啟動 Toybox 網頁。

這與 Basic、Digital Human 筆記本的分格不同，請以你開啟的筆記本標示為準。

完成後，點選畫面提供的網頁連結。

**Step 4：生成第一支影片**

建議第一次先測試：

- 片長：5 秒
- 解析度：480P
- 比例：9:16
- 模式：參考生成

先上傳人物照片，再描述人物動作、鏡頭和對白。

如果要做 AI 網紅，建議固定使用同一張正式角色定裝照作為參考。

**Step 5：檢查成果**

生成後，不要只確認影片能播放。

還應該檢查：

- 五官是否與參考人物一致
- 服裝是否跑掉
- 中文發音是否自然
- 嘴型是否對得上
- 有沒有產生多餘字幕
- 鏡頭及動作是否符合需求

H3 有官方提示詞格式，專案建議參考生成採英文描述、台詞保留原語言。上面的中文台詞是需求示意，正式生成前仍應轉成對應工作流的提示詞。

可以利用 Toybox 的提示詞改寫功能，讓提示詞更符合模型需求。

## 四、教學二：安裝 h3-colab-skill，讓 Codex 自動生成

接下來這個專案，才是我認為最值得 AI Agent 使用者研究的部分。

它的正式 Skill 名稱叫做：

`h3-multimodal-colab`

目前支援 Claude Code、Codex，以及其他能操作本機命令列的 AI Agent。

主要概念是：

你不用再自己開啟 Colab、下載模型、設定工作流。

只要告訴 AI 你想做什麼，它就會協助完成操作流程。

### Step 1：安裝 Skill

作者已經提供 AI Agent 專用的安裝指南。

你可以直接在 Codex 或 Claude Code 中貼上：

```text
請先閱讀以下專案作者提供的安裝指南：

https://github.com/dseditor/h3-colab-skill/blob/main/INSTALL_FOR_AGENTS.md

我想安裝 h3-multimodal-colab Skill。

開始安裝前，請先告訴我：

1. 這個 Skill 可以完成哪些工作？
2. 需要哪些 Google 訂閱？
3. 會安裝哪些本機工具？
4. 如何使用我的 Colab GPU？
5. 什麼時候需要 Google 帳號授權？

請先靜態審查安裝腳本與連帶下載內容，說明來源版本、讀寫路徑、權限與網路目的地。
預設安裝在目前專案的技能目錄；若需全域工具，請另列出。
請等我同意後，再執行安裝。
```

依作者安裝指南，本機會涉及 uv、Python 3.12、google-colab-cli 0.7.4 與 Skill 檔案；ComfyUI 與模型則在 Colab 環境安裝／下載。這是流程說明，本文未執行該安裝或審查完整供應鏈。

第一次使用時，需要透過 Google 帳號完成授權。

注意：這是讓程式存取你帳號中的 Colab 運算資源，因此應該先確認授權內容。

### Step 2：選擇生成環境

Skill 可以選擇兩種執行模式。

**模式 A：Google Colab**

適合沒有 NVIDIA 顯示卡的使用者。

需要使用 Colab 運算單元，每次啟動環境時可能需要重新下載模型。

**模式 B：本機 ComfyUI Desktop**

作者本機指南以 ComfyUI Desktop 與至少 16GB 顯示記憶體的 NVIDIA 顯示卡為條件；文件中的路徑與操作範例以 Windows 為主，其他系統仍須另行確認。

模型下載一次後，就能重複使用。

如果你使用的是 MacBook Pro M 系列，建議先選 Colab，因為目前作者的本機方案是以 NVIDIA GPU 為主要條件。

### Step 3：交辦 AI 影音生成任務

假設你正在經營一個 AI 網紅角色。

你可以直接對 Codex 說：

```text
請使用 h3-multimodal-colab Skill，
幫我的 AI 網紅製作一支 15 秒的直式短片。

角色：
使用我提供的角色定裝照。

影片風格：
真人寫實、台灣生活 Vlog、自然跟拍。

劇情：
第一段 5 秒：女生走進咖啡廳。
第二段 5 秒：她看到帳單，露出震驚表情。
第三段 5 秒：她對店員說出搞笑台詞，
最後出現冷面幽默反轉。

製作需求：

1. 保持角色五官、髮型、服裝一致。
2. 使用 9:16 直式畫面。
3. 先以 L4、480P 測試。
4. 中文對白使用台灣華語。
5. 影片不要字幕。
6. 請先整理分鏡與生成提示詞。
7. 先讓我確認規格，再開始批次生成。
8. 完成後下載影片，檢查畫面和聲音。
9. 詢問我要不要繼續修改，再決定是否關閉 GPU。
```

這樣 Codex 就能依照 Skill 的規則，規劃生成工作並進行操作。

當然，AI 產出的角色一致性、動作和對白仍需要驗收，不代表一次生成就一定成功。

## 五、第二個專案最重要的功能：批次生成

我認為 `h3-colab-skill` 最有價值的地方，就是它的批次工作機制。

例如你有一支 30 秒的 AI 短劇。

傳統流程可能是：

1. 打開圖片生成工具，產生分鏡。
2. 下載分鏡圖片。
3. 打開 H3，逐張上傳。
4. 逐段生成影片。
5. 下載所有影片。
6. 打開配音工具，產生語音。
7. 將素材匯入剪輯軟體。

如果每次都要切換工具，會花不少時間。

但第二個專案可以讓 Agent 把工作整理成 `manifest.json`。

支援的工作類型包括：

| 類型 | 功能 |
|---|---|
| `image` | 圖片生成與編輯 |
| `video` | 影片生成 |
| `video + extend` | 延伸既有影片 |
| `tts` | 語音生成 |

還能利用 `@id` 引用前面任務的輸出成果。

也就是說，前一個工作生成的圖片，可以接著交給後續的影片生成工作使用。

這才是真正值得延伸研究的地方。

未來可以把它和 AI 編劇、分鏡、剪輯工作流串接起來。

不過要提醒，批次執行並不等於完全無人監督。角色不一致、動作錯誤或生成失敗時，仍然需要針對個別片段調整。

## 六、Google Colab 會花多少運算單元？

這也是大家很關心的問題。

根據 [h3-colab-skill README](https://github.com/dseditor/h3-colab-skill#需要什麼) 的估計（非 Colab 固定費率）：

| GPU | 作者估計每小時消耗 | Skill 預設解析度 |
|---|---:|---|
| L4 | 約 1.5 個運算單元 | 480P |
| G4 | 約 11 個運算單元 | 720P |

作者在 2026 年 11 月 4 日公布的一組 L4 測試，包含：

- 啟動 Colab
- 安裝環境與下載模型
- 兩張參考圖進行圖片編輯
- 生成一支 5 秒影片
- 生成約 6 秒配音
- 完成後關閉 GPU

整批約花費 10.1 分鐘、0.5 個運算單元。

這是作者在特定環境下的實測，不能視為所有影片都能達到相同速度。

而且 GPU 供應、Colab 政策、實際點數消耗，都可能變動。

建議第一次先做一支 5 秒影片，確認自己的帳號可以正常執行，再開始大量生成。

## 七、Skill 還能自動管理 GPU

這是另一個我覺得很實用的功能。

因為很多人使用 Colab 時，會遇到兩個問題。

第一個是每次啟動都要重新下載模型。

第二個是影片做完後，忘記關閉 GPU。

`h3-colab-skill` 設計了相關管理機制：

- 開始工作前檢查剩餘運算單元。
- 批次任務有執行時間上限。
- 工作完成後，預設暫時保留 GPU 15 分鐘；保留期間仍可能消耗運算單元。
- 如果需要修改，可以沿用同一個環境。
- 如果沒有新的任務，依專案設計，本機閒置計時器會嘗試自動關閉 GPU；仍應讀回執行階段狀態確認釋放。
- 任務失敗或中斷時，會嘗試釋放 GPU。

換句話說，它不只是影片生成 Skill，也包含部分 Colab 資源管理功能。

對於經常使用 AI Agent 批次生成素材的人，這種管理方式相當有價值。

## 八、使用之前要注意什麼？

### 1. 開源不代表運算免費

兩個 GitHub 專案可以免費取得程式碼，但執行 Colab GPU 可能會消耗付費方案的運算單元。

因此，不能把「開源」直接理解成「無限免費生成影片」。

### 2. 模型授權要分開看

`h3-colab-skill` 專案採 MIT 授權。

但 MiniMax H3、P-H3-Image，以及附加的 LoRA 模型，各有不同授權條款。

如果要用在商業接案、企業服務或對外提供生成平台，應該先確認模型授權。

### 3. 留意 Colab 連線安全

第一個專案如果使用 Cloudflare 公開連線網址，作者提醒該網址沒有密碼保護。

因此不要把連線網址貼到公開社群。

第二個專案則需要 Google 帳號授權，也應確認授權範圍並保護本機憑證。

### 4. AI 生成還需要人工驗收

特別是 AI 網紅與連載短劇，人物的一致性非常重要。

即使使用相同參考照片，仍可能出現：

- 人物臉型改變
- 服裝細節不一致
- 台詞不完整
- 動作不連貫
- 鏡頭方向錯誤

最好的做法，是先建立正式角色素材，再將產片流程標準化。

## 九、我會怎麼應用在 AI 網紅與短劇工作流？

以我目前研究的 AI 網紅、短劇、Codex 自動剪輯工作流來看，我會把這兩個專案分成不同用途。

**第一階段：使用 H3 Toybox 測試生成品質。**

先測試角色的一致性、中文口音、嘴型，以及動作生成是否符合預期。

這個階段的重點是確認模型能做到什麼。

**第二階段：使用 h3-colab-skill 自動化批次產片。**

讓 Codex 負責：

1. 整理短劇腳本。
2. 拆解分鏡。
3. 產生影片提示詞。
4. 建立生成工作清單。
5. 啟動 Colab GPU。
6. 批次生成圖片、影片與音訊。
7. 下載並檢查素材。

接著，再把產出的素材交給既有的 Concat、FFmpeg 或 DaVinci Resolve 自動剪輯流程。

如此一來，就能逐步建立一套從腳本到影片的 AI Agent 製作流程。

當然，這是值得實作驗證的整合方向，並不是這兩個專案已經內建完整的成片剪輯功能。

## 結語：AI 影音創作，正在從工具操作走向 Agent 自動化

我認為這兩個專案最大的啟發，不只是 MiniMax H3 終於可以透過 Colab 使用。

更重要的是，它們讓我們看到 AI 影音工具正在發生什麼變化。

以前，我們需要學會操作各種 AI 工具。

現在，我們開始讓 AI Agent 替我們操作工具。

從生成圖片、產生影片、生成語音，到下載素材，越來越多步驟可以交給 Agent 處理。

所以，我的建議是：

如果你是初學者，先從 `minimax-h3-colab` 的 H3 Toybox 開始。

如果你已經熟悉 Codex 或 Claude Code，想建立自己的 AI 網紅或短劇自動化工作流，那麼 `h3-colab-skill` 更值得深入研究。

**未來 AI 影音製作的競爭力，不只是誰會用更多生成工具，而是誰能把創作流程變成可重複、可驗證、可持續改進的 AI Agent 工作流。**

## 常見問答 (FAQ)

### Q1：沒有 NVIDIA 顯示卡，Mac 也能用 MiniMax H3 嗎？

可以採本文的 Colab 路線，把生成運算交給雲端 GPU，本機主要負責操作與接收檔案。仍須具備作者文件要求的帳號資格、可用運算單元與 GPU 配額；作者的本機方案則以 NVIDIA GPU 為條件。

### Q2：minimax-h3-colab 和 h3-colab-skill 應該選哪個？

想先透過網頁調整參數、理解生成品質，可從 minimax-h3-colab 的 Toybox 開始。若已有能執行本機指令的 Codex 或 Claude Code，且需要批次處理圖片、影片與配音，可研究 h3-colab-skill 的工作清單與 Colab 管理流程。

### Q3：開源代表免費產片、也能直接完成剪輯嗎？

程式碼可取得不代表 GPU 運算免費。Colab 仍可能消耗付費運算單元，模型與附加素材也各有授權條款。這兩個專案主要處理生成與素材回收，完整短劇仍須剪輯與人工驗收，不能把批次生成視為成片品質保證。
