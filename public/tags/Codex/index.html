    Codex MCP 影音行銷
    Codex × Concat 實測：打造 AI 短影音自動剪輯工作流

    以前要做一支短影音，得自己找素材、排時間軸、剪接、上字幕、配樂，再匯出影片。AI 即使幫忙寫好文案，接下來仍要打開剪輯軟體，一段一段手動調整。 最近我改用開源剪輯軟體 Concat 做了一次實驗：讓 Codex 透過本機 MCP Bridge 呼叫 Concat 的 API，先輸出短測試片，再完成一支 30 秒招生短影音。接著，我把反覆驗證過的操作方式整理成專案內的 concat-video-editor Skill，讓剪輯流程可以再次使用。 這次經驗最有意思的地方，不是「講一句話就能剪出完美影片」，而是把一套剪輯流程拆成 Codex 能執行、檢查和重複操作的步驟。 本文記錄的是 2026 年 10 月 18 日，以 Concat 0.2.7 進行的本機實測。Concat 仍在持續開發，功能與 API 可能更新。官方 MCP 文件當日仍標示內建 MCP 尚未發布；同日的 Issue #337 則宣布官方開始投入內建 MCP 傳輸的開發。若要照本文操作，請先查看官方最新版本與文件。 Concat、MCP Bridge 和 Skill 各自負責什麼？Concat 是一套本機影片剪輯軟體，提供多軌時間軸、動態文字、配樂等剪輯能力，也有可供程式呼叫的 JSON-RPC API。這次實測使用的是 Concat 0.2.7。 串接時有三個容易混淆的部分： 元件 工作 這次實作 Concat API 讓外部程式呼叫剪輯功能 使用 Concat 提供的本機 JSON-RPC API MCP Bridge 把 AI 工具的 MCP 呼叫轉成 Concat API 指令 自行建立的本機 Python Bridge Skill 告訴 Codex 如何依照 SOP 規劃剪輯、操作和驗收 專案內的 concat-video-editor Skill 可把整體流程想成： 123456789剪輯需求 → Codex → concat-video-editor Skill ↓ MCP Bridge ↓ Concat JSON-RPC API ↓ 時間軸、影片與剪輯專案 ↓ 輸出與驗收 Bridge 解決「怎麼連上工具」；Skill 解決「連上之後怎麼按照規則完成工作」。只有 Skill、沒有可用的 MCP 連線，Codex 就不能呼叫 Concat；只有 Bridge、沒有剪輯 SOP，也不代表每次操作都會排出正確時間軸。 先看清楚 Concat 的 MCP 狀態這篇的實測版本是 0.2.7。官方開發者文件在 2026 年 10 月 18 日標示：Concat 的 API 與 JSON-RPC 傳輸已存在，但正式隨產品發布的 MCP Server 尚未到位；官方提供的當下作法，是以一個 MCP Server 包裝 JSON-RPC socket。官方同日也在 Issue #337 宣布開始開發內建的 MCP 傳輸。因此，本文的 Bridge 是我當時實際建立與測試的方案，不能直接推論為目前所有版本都需要自建 Bridge。 建立本機 Bridge：先連線，再操作剪輯這次使用 Apple Silicon MacBook Pro M2。Bridge 以 Python FastMCP 建立，共提供 22 個 MCP 工具，涵蓋專案管理、媒體匯入、片段編輯、文字、預覽影格、匯出及工作狀態查詢。這是我自行實作的工具數量，不代表 Concat 官方 MCP Server 的工具清單。 Concat Remote API 在本機監聽，例如 127.0.0.1:7420，並使用 Token 驗證。我的 Bridge 將 Token 放在本機環境檔，限制檔案權限，不把憑證寫進程式碼或公開文章。實際設定時也應把專案與輸出限制在指定工作資料夾，並先用全新的測試專案驗證。 在修改 Codex 的 MCP 設定前，我先備份原設定，再請 Codex 依實際位置填入 Bridge 執行檔與程式路徑。這次的 Bridge 另外加入了 macOS 自動啟動：連線被拒絕時，嘗試執行 &#x2F;usr&#x2F;bin&#x2F;open -g -b app.concat.editor，最多等 15 秒讓 Remote API 就緒。這是我自行加入的 Bridge 功能，不是每一套串接都會自動啟動 Concat；一般情況仍要先開啟軟體。 Codex 的 MCP 設定會指向本機 Python 執行環境與 Bridge 程式，概念如下；路徑要換成自己的實際位置： 12345[mcp_servers.concat]command = 秒測試片我先使用簡單測試影片與繁體中文標題「Codex 連線測試」，輸出約 2.5 秒的 H.264 MP4。測試同時檢查： 匯出工作是否收到 export.done。 解析度、影格率、片長是否符合預期。 影片與音訊能否完整解碼。 指定時間點的預覽影格是否正確。 Concat 原生專案能否儲存與重新開啟。 原始測試素材是否保持不變。 匯出工具回傳「已啟動」不等於檔案已完成。Concat 的匯出工作是非同步的，必須追蹤 job 並等待完成事件；若連線在等待期間中斷，也先確認舊工作與輸出狀態，再決定是否重跑，避免重複輸出。 再完成 30 秒招生短影音小測試通過後，我才交給 Codex 三段素材與一段已授權的配樂，製作「AI 新時代」招生短影音。需求是： 9:16 直式，輸出 1080 × 1920。 整理操作畫面精華，加入大字文案與簡單動態文字。 不加旁白，搭配背景音樂。 片尾安排課程名稱與「立即洽詢課程」CTA。 保留原始素材和 Concat 專案，輸出新版本，不上傳、不發布。 最後輸出 AI新時代-30秒招生短影音-v02.mp4，並檢查片長、影像與音訊。這次成果證明的是：在這批素材與這套工作流程下，Codex 能透過 Concat 完成一支 30 秒影片；它不能代表任何素材、長度或畫幅都會有同樣結果。 把成功流程封裝成 concat-video-editor Skill第一次剪成功後，我把如何讀取素材、挑選片段、安排軌道、加文字和配樂、等待匯出、檢查結果等操作，整理成專案內的 concat-video-editor Skill。它保留在專案裡，不修改全域 Skill，也不包含 MCP Bridge、Python 虛擬環境或 Token。使用 Skill 前，Bridge 必須已經能正常連線。 固定規格的影片可以再寫成 操作體驗仍需要人工檢查。規格檢查通過，不等於影片節奏、文案與音樂一定適合觀眾。 遇到的狀況 原因與修正方式 片段位置沒有落在預期時間 不同欄位要用對應的 API 命令。這次以 trimClip、moveClips 處理裁切與移動，操作後重新讀取時間軸確認位置。 標題被排到影片後面 同一軌道的片段可能互相推移。影片、標題、補充文字、品牌字樣與 CTA 視需要分軌，新增後再檢查時間軸。
