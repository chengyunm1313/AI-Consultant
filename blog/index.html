    最近看到一位開發者分享自己的 AI 工作流，讓我覺得很有意思。 依照那則分享，他買了三台 Mac，使用兩個 Claude Code 高階訂閱帳號，總共執行八個 AI Agents。每個 Agent 都有自己的 Tart 虛擬機，再透過 Herdr、Tailscale 和 Claude Code Remote Control，讓整套系統可以遠端操作、長時間執行。 他的工作包含開發、寫書、製作講義、簡報、研究新技術，甚至整理郵件與 AI 新聞。這些工作逐漸從自己動手，變成由 AI Agent 負責。 而且不只是坐在電腦前操作，出差在外也能透過手機或筆電，接手原本正在執行的工作。 看到這裡，我開始思考：我們真的需要三台 Mac、八個 Agent，才能打造自己的 24 小時 AI 團隊嗎？ 研究之後，我發現答案是不一定。真正值得學習的，是這套架構背後的設計思維。 這篇就來拆解核心技術、實際安裝方法、成本，以及如何利用現有設備，打造自己的 24×7 AI Agent 工作站。 閱讀範圍：開場的設備數量、訂閱數量與工作內容，是作者轉述的開發者分享；本文未取得原始分享連結，並非本文實測紀錄。以下安裝步驟供讀者實作驗證；Dispatcher 與跨設備接力流程屬於延伸設計，不是安裝工具後就會自動具備的功能。 一、24×7 AI Agent 和一般 AI 助手差在哪裡？我們平常使用 ChatGPT、Claude、Gemini，大部分都是這樣： 打開聊天介面。 輸入問題或交代工作。 等待 AI 回答。 自己檢查結果。 再交代下一件事。 這種模式比較像是「AI 助手」。24×7 AI Agent 則像是一個隨時待命的數位工作團隊，例如可以規劃這樣的工作日： 時間 Agent 預期工作 早上六點 研究 Agent 整理昨天的重要 AI 新聞 早上七點 教材 Agent 根據研究結果，產生技術教學文章草稿 早上八點 開發 Agent 檢查 GitHub 專案、執行測試並整理異常 下午 影音 Agent 處理影片素材、字幕及剪輯工作 晚上 幕僚長 Agent 彙整成果，產生每日報告 你不需要一直坐在電腦前面盯著它們。不過，24×7 在線，不等於 AI 真的會自動工作。 要做到真正的自動化，至少需要五個部分： 持續運作的電腦或伺服器。 能執行工作的 AI Agent。 排程或事件觸發機制。 任務管理與失敗重試機制。 遠端監控及通知機制。 少了其中幾個，可能只是讓 AI 一直開著，卻沒有真正提高工作效率。 二、先認識五個核心工具，各自解決什麼問題？1. Claude Code：負責工作的 AI 員工Claude Code 是 Anthropic 推出的 AI Coding Agent。雖然名字裡有 Code，但它不只能寫程式。 只要工作能透過檔案、指令、API 或其他支援的工具完成，就有機會交給它處理，例如： 開發網站與應用程式、修改 GitHub 專案。 撰寫 Markdown 教材、整理研究資料及產生簡報內容。 執行 Python 程式、批次處理文件。 操作已設定且支援的外部工具。 與一般聊天式 AI 最大的差別，是 Claude Code 可以直接在工作環境中執行操作。例如你交代： 幫我檢查這個網站專案，把錯誤修好，測試通過後整理修改報告。 它可以讀取程式碼、修改檔案、執行測試，再回報結果；前提是你已提供適當的工作環境、工具與權限。 2. Herdr：集中管理整隊 Agent 的工作階段如果你同時開啟好幾個 Claude Code、Codex 或 OpenCode，可能會遇到這種情況：一個視窗正在寫程式、另一個跑測試、第三個等待回答，第四個則不知道什麼時候已經失敗。最後，你花很多時間切換視窗、檢查進度。 Herdr 就是想改善這類問題。它能集中管理多個 Agent 的終端機工作階段；但必須先分清楚目前官方的兩條產品路線： Herdr TUI：終端機介面，使用自己的背景 server；本文的 herdr 指令與 herdrdev&#x2F;herdr repo 屬於這條路線。 Herdr App、手機 App 與 Herdr Core：另一套以 Core 管理工作階段的架構，須依對應文件設定。官方首頁說明，TUI 與 App 不共用 Agent，不能假設 TUI 開出的工作階段會直接出現在 App。 Herdr TUI 的主要能力包括： 能力 實際意義 工作階段持續存在 終端機關閉或 SSH 中斷後，背景 server 可維持窗格內的程序；主機關機仍會中斷工作 跨電腦管理 透過 SSH 連接其他設備上的工作階段，仍須具備連線與驗證條件 Agent 狀態監控 在支援的整合與狀態回報機制下，辨識工作中、閒置或等待輸入等狀態 程式化操作 提供 CLI 與 Socket API，讓其他程式管理窗格及工作階段 這些介面讓另一個 AI Agent 有機會參與協調工作。不過，Herdr 的工作階段管理不能直接取代完整的任務排程、持久化佇列、重試、權限審核與成果驗收。 功能與指令請以安裝版本的 TUI 文件及 Socket API 文件為準。 3. Tailscale：讓不同電腦建立私人連線假設你有家裡的 Mac、辦公室的 Windows，以及 Oracle Cloud 上的 Linux VM。這三台設備可能位於不同網路。 傳統做法可能需要處理固定 IP、Port Forwarding、防火牆與 VPN。Tailscale 利用 WireGuard 技術簡化私人加密網路的建立。設備加入同一個 Tailnet，並符合存取權限設定後，就能透過私人網路連線。 你可以人在外面用筆電連回家裡的 Mac，或讓雲端 Linux 連接辦公室的 Windows。不過，Tailscale 負責的是網路連線，Agent 的啟動與派工仍要另外設定。 4. Tart：在有需要時提供獨立虛擬機Tart 是針對 Apple Silicon 設計的虛擬機管理工具，可以執行 macOS 與 Linux VM；原始碼位於 cirruslabs&#x2F;tart。 開場分享採用的方式，是讓不同 Agent 在各自的 Tart VM 工作。這能減少環境衝突，例如 Agent A 安裝 Node.js 套件、Agent B 修改 Python 環境、Agent C 更新系統設定時，不必全部共用同一套作業系統環境。 但虛擬機需要額外 CPU、記憶體與磁碟空間。如果 Mac 只有 16GB RAM，我不建議一開始就替每個 Agent 建立一台 VM。 比較實際的方式，是先用不同工作目錄搭配 Git Worktree；確實需要隔離作業系統或相依套件時，再考慮 Tart。使用前也應確認所選版本的授權與使用條件，不把「可查看原始碼」直接當成所有用途都免費或無限制。 5. Claude Code Remote Control：人在外面也能接手假設 Claude Code 正在家裡的 Mac 工作，而你已經出門。當它需要確認下一步時，可以透過 Remote Control，從支援的 Claude 網頁或手機介面接續本機工作階段。 在 Claude Code 裡可以輸入： 1/remote-control 實際執行的仍是原本的電腦，電腦必須保持開機、Claude 程序持續運作且能連網。休眠或網路中斷時會影響可用性，恢復後的重新連線行為也要實測。 可用性受到訂閱、登入方式、組織政策與版本影響；目前官方文件說明 API key 不支援 Remote Control，使用前應查看最新需求。它與透過 Tailscale 建立 SSH 連線是兩條不同的遠端操作路徑，啟用 Remote Control 本身不要求先安裝 Tailscale。 新聞、GitHub 研究 Linux VM Developer 網站開發、程式測試 Mac Writer 教材、文章、講義 Mac Media 影片、字幕、轉檔 Windows 再建立 Dispatcher 負責派工。例如你交代： 研究最近一週值得教學的 AI Agent 開源專案，選出三個，產生教學文章，最後更新課程網站。 Dispatcher 可以拆成三個有依賴關係的任務： 任務 A：研究。 接力工作流。但要做到這件事，還需要真正的任務管理系統，可以使用 SQLite、PostgreSQL、Redis 或適合的持久化佇列方案。 最基本的任務資料可以長這樣： 12345678910111213&#123; &quot;task_id&quot;: &quot;TASK-001&quot;, &quot;title&quot;: &quot;研究 AI Agent 開源專案&quot;,     AI 影片運鏡提示詞教學：12 種鏡頭技巧，讓畫面更有電影感

    你有沒有遇過這種情況？明明 AI 生成的人物很漂亮、場景也很精緻，但是影片看起來就是少了一點電影感。人物站在原地、鏡頭不太會動，整支影片看起來像是一張會動的照片。有時候想讓畫面更精彩，在提示詞裡加上：「電影級運鏡」、「專業攝影」、「好萊塢電影質感」、「動態鏡頭」。結果呢？AI 不是把人物突然放大，就是讓攝影機莫名其妙地亂轉，甚至連人物的臉都變了。 其實問題可能不在 AI 影片模型，而是我們沒有把「運鏡」描述清楚。最近看到一支整理 12 種鏡頭技巧的示範影片，包括推進、拉遠、跟拍、環繞、滑動變焦、子彈時間等。本文會區分攝影機移動、變焦與時間效果，避免把所有技巧混為一談。 這些觀念適合正在學習 Google Flow、Seedance 等 AI 影片生成工具的新手。本文提示詞是練習範例，實際支援的參考素材、片長與控制方式，仍依工具版本、模型與方案而定。所以這篇文章，我想用最容易理解的方式，帶大家學會： 什麼是運鏡？為什麼能增加電影感？ 12 種常見運鏡各有什麼效果？ 如何把運鏡寫成 AI 能理解的中文提示詞？ 如何應用在 AI 網紅、短劇、商品廣告與短影音？ 怎麼避免 AI 運鏡時人物變形、場景亂跳？ 不用先學會專業攝影，也不用背一堆英文術語。只要理解攝影機怎麼動，就能開始寫出更好的提示詞。 一、先搞懂：運鏡不是單純把畫面放大在學習 12 種運鏡之前，先建立一個重要觀念。 攝影機移動，不等於鏡頭變焦。 例如，你想拍攝一位女生站在街道上。你可以使用兩種方式讓她在畫面中變大。 方法 A：攝影機向前移動 攝影機真的向女生靠近。隨著攝影機移動，旁邊的建築物、路燈和車輛，也會因為觀察位置改變而產生不同程度的位移。這種現象叫做「空間視差」（Parallax）。它能讓觀眾更明顯地感受到立體空間與前後層次；景深則是畫面中可接受清晰的距離範圍，兩者並不相同。 方法 B：攝影機不動，直接變焦放大 攝影機保持在原地，透過調整鏡頭焦距，讓女生在畫面中變大。這時候畫面的取景範圍會改變，但不會產生攝影機實際移動帶來的視差效果。兩者看起來都是人物變大，但呈現的空間感不同。這也是為什麼，只告訴 AI「鏡頭慢慢靠近人物」，有時候它會直接把畫面放大。因為這句話沒有明確說明，是攝影機移動，還是鏡頭變焦。所以，我建議大家在寫運鏡提示詞時，盡量描述具體的攝影機動作。 二、AI 運鏡提示詞的萬用公式先記住這個公式： 人物與動作＋起始構圖＋攝影機移動方式＋移動速度＋結束構圖＋限制條件 我們直接比較。 普通寫法「一位美女站在街上，鏡頭緩慢推進，電影感。」這句話不是不能用，而是給 AI 太多自由發揮的空間。 改良寫法「一位成年女性站在黃昏的城市街道，神情平靜地望向遠方。鏡頭從人物腰部以上的中景開始。攝影機沿直線緩慢向前移動，逐漸靠近人物，兩側街景隨著攝影機移動產生自然的空間視差。最後停在人物臉部近景，短暫穩定構圖。全程保持人物五官、服裝、髮型與場景一致，單一連續鏡頭，不切換畫面。」你會發現，改良後的提示詞多了幾個關鍵： 從哪裡開始： 腰部以上的中景。 怎麼移動： 沿直線緩慢向前。 背景怎麼變化： 產生自然空間視差。 在哪裡結束： 臉部近景。 哪些不能改變： 人物身分與場景。 這樣 AI 就比較容易理解你真正想要的鏡頭效果。接下來，我們進入 12 種運鏡的實戰教學。 三、如何寫出 12 種運鏡與時間效果提示詞？為了方便理解，我把它們分成三個類別。 第一類：引導觀眾視線的基本運鏡 1. 推進（Dolly In）效果：讓觀眾注意某個人物、表情或重要細節。 推進是電影中非常常見的運鏡。例如，主角突然發現一件可怕的事情。攝影機從中景緩慢向前推進，最後停在他的臉部特寫。即使人物沒有說話，觀眾也能感受到他的情緒正在變化。 適用情境： 人物情緒特寫 AI 網紅開場 商品細節介紹 短劇重要對白 營造緊張與壓迫感 AI 提示詞： 鏡頭從人物中景開始，攝影機沿直線緩慢向前移動，逐漸靠近人物。背景自然向畫面兩側滑動，產生真實的空間視差。最後停在人物臉部近景，鏡頭平穩收住，人物保持在原地。 這裡有一個重點。如果希望鏡頭有明顯的空間感，可以加入：「前景與背景產生自然的空間視差。」它能進一步說明你要的是實際移動攝影機，而不只是畫面放大。 2. 拉遠（Dolly Out）效果：逐漸揭露環境，製造孤獨感、反差或驚喜。 拉遠和推進剛好相反。例如，畫面一開始是一位女生的臉部特寫。攝影機慢慢後退。觀眾才發現她竟然獨自站在一個巨大的廢棄工廠中央。原本只是普通的人物特寫，瞬間多了故事感。 適用情境： 介紹大型場景 展現人物孤獨感 短劇結尾 揭露意想不到的環境 商品使用情境展示 AI 提示詞： 攝影機從人物臉部近景開始，沿直線緩慢向後移動，逐漸揭露人物全身與周圍環境。畫面從近景轉變成寬闊的全景，最後平穩停住。人物始終站在原地，沒有跟著攝影機移動。 注意最後一句。如果沒有寫清楚，AI 有時候會讓人物跟著鏡頭倒退，造成不自然的畫面。 3. 橫搖（Pan）效果：把觀眾的注意力從一個地方轉向另一個地方。 想像攝影機架在腳架上。攝影機不移動位置，只把鏡頭從左轉到右。這就是橫搖。例如，先拍攝空蕩蕩的走廊，再慢慢向右轉，才發現門口站著一個神祕人物。這種運鏡很適合用來逐步揭露資訊。 適用情境： 介紹環境 依序展示多位人物 短劇轉移注意力 展示商品陳列 營造懸疑感 AI 提示詞： 攝影機固定在原地，鏡頭從左向右緩慢水平旋轉。畫面先呈現空蕩的走廊，再逐漸揭露右側站立的人物，最後停在人物中景。攝影機本身不向左右平移，只有拍攝方向改變。 記住： 橫搖是攝影機轉動方向，不是整台攝影機向旁邊滑動。 4. 向上搖（Tilt Up）效果：由下往上揭露人物，展現造型、身分或氣勢。 這種運鏡非常適合 AI 網紅與時尚影片。例如，拍攝一位穿著高級訂製服的模特兒。畫面先從高跟鞋開始，慢慢向上移動視線。接著展示裙裝、腰部、肩膀，最後停在人物臉部。這樣的鏡頭比直接拍全身更有儀式感。 適用情境： 時尚穿搭 人物登場 展示角色服裝 英雄出場 展示高大建築物 AI 提示詞： Vlog，多少會有一點腳步起伏、細微晃動。適度加入這些動態，反而能讓影片更像真人拍攝。 適用情境： AI 網紅生活 Vlog 第一人稱影片 街頭探店 紀錄片風格 緊張追逐 AI 提示詞： 攝影機以手持方式近距離跟隨人物行走，隨著腳步產生自然、細微的上下起伏與晃動。人物臉部保持可辨識且大致清晰，晃動受到控制，呈現真實生活紀錄片的攝影質感。 這裡有個常見錯誤。很多人會寫：「劇烈手持晃動。」結果 AI 3D 模型展示 電影英雄鏡頭 AI 提示詞： 人物站在原地保持自然姿勢，攝影機與人物維持固定距離，從正面沿著圓弧軌道向人物左側移動，環繞約 90 度。拍攝角度從人物正面逐漸轉為側面，背景產生自然的空間視差，最後平穩停止。人物本身不旋轉。 環繞最常遇到的問題，就是 AI 讓人物自己轉圈。所以一定要強調：「攝影機環繞人物，人物保持原地不自轉。」另外，初學者不一定要直接要求 360 度環繞。可以先測試 這是我覺得最值得深入研究的一個技巧。它並不是普通的變焦。而是讓攝影機移動與鏡頭變焦同時進行。例如：攝影機向人物靠近，同時向外變焦。如果兩個動作配合得當，可以讓人物在畫面中的大小保持接近不變，但背景透視卻發生明顯改變。經典滑動變焦經常用來表現人物突然受到重大衝擊。 先從主體大小大致不變的經典版本開始，比較容易檢查生成效果。攝影機前移造成視點改變，再以縮短焦距補償主體大小；背景相對主體的比例因此改變。這也是 Adobe 對 Dolly Zoom 的說明所強調的移動與變焦同步控制。 適用情境： 角色突然發現真相 恐怖電影 心理驚悚 重大劇情反轉 超現實視覺效果 AI 提示詞： 一位成年女性站在停車場中央，背後有整齊排列的汽車與遠方建築。攝影機從正面中景開始，緩慢沿直線靠近女性，同時縮短焦距、向外變焦，兩個動作同步，使人物在畫面中的大小保持大致不變。背景相對人物的比例與透視逐漸改變，形成不安的空間感。人物保持原地不動，五官、服裝與場景連續一致，最後平穩停止。 這個技巧要特別提醒大家。Dolly Zoom 涉及攝影機位置與焦距的同步控制，對生成模型來說比較困難。AI 有時候會直接放大人物，卻沒有產生真正的透視變化。因此建議先用簡單場景實驗，再嘗試複雜的背景。 11. 子彈時間（Bullet Time）效果：讓關鍵動作近乎靜止，但攝影機仍然可以改變觀察角度。 如果你看過《駭客任務》，應該對這類視覺效果不陌生。角色在空中做出動作，時間彷彿停止。但觀眾的視角還能繞著人物改變。這就是子彈時間最有代表性的效果。嚴格來說，它不是單純的攝影機運動，而是結合時間控制與視角變化的技術。 適用情境： 動作電影 產品動態廣告 物體飛行 特殊事件瞬間 超現實短片 AI 提示詞： 人物向前拋出一個物件，在物件即將飛過鏡頭前方的瞬間，時間幾乎完全凝固。物件停留在半空中，攝影機沿著物件周圍快速環繞約 90 度，從不同角度呈現人物與物件之間的空間關係。最後時間恢復正常，物件繼續向前飛行。 這類畫面對 AI 生成的難度較高。如果人物手部與物件的接觸關係很複雜，可能出現物件變形或位置不連續的情況。可以先從簡單物件開始練習。 12. 慢動作（Slow Motion）效果：放大關鍵瞬間，強調情緒與動作細節。 慢動作其實不是運鏡，而是時間控制。但在 AI 影片製作時，它經常與運鏡搭配使用。例如：女生甩動長髮。水滴從頭髮上飛出。如果使用正常速度，可能一瞬間就結束。但改成慢動作，就能仔細呈現頭髮與水滴的運動。 適用情境： 時尚形象影片 飲料與美食廣告 人物情緒 動作特寫 商品材質展示 AI 提示詞： 一位成年女性站在柔和的夕陽下，緩慢轉頭，長髮隨著動作自然甩動。在頭髮揚起的關鍵瞬間，畫面進入四分之一速度的慢動作，清楚呈現髮絲與光線的細節。隨後逐漸恢復正常速度，攝影機保持穩定，人物臉部與髮型一致。 慢動作要注意一個問題： 不是整支影片越慢越有電影感。 如果所有動作都很慢，反而會讓影片失去節奏。真正好用的方式，是讓一般動作維持正常速度，只在關鍵瞬間放慢。 四、AI 運鏡應該服務故事，而不是為了炫技。 五、如何選用運鏡，組成 15 秒 AI 短影音？假設今天要製作一支 15 秒的 AI 課程形象廣告。主角是一位 AI 講師。場景是現代化教室。我們可以設計三個鏡頭。 鏡頭一：0～5 秒｜推進目的：建立講師的專業形象。提示詞： 一位臺灣男性 AI 講師站在現代化教室前方，背後是大型 AI 科技展示螢幕。攝影機從講師正面中遠景開始，緩慢向前推進，最後停在胸部以上的中近景。講師自然微笑，目光看向鏡頭，畫面呈現專業科技形象廣告的攝影質感。 鏡頭二：5～10 秒｜橫搖目的：展示課堂互動。提示詞： 鏡頭從教室左側的學員開始，攝影機固定在原地，由左向右緩慢水平旋轉，依序展示正在操作電腦的學員，最後停在前方講課的講師身上。畫面自然流暢，凸顯課堂的實際互動。 鏡頭三：10～15 秒｜急推變焦目的：增加視覺衝擊，強調結尾。提示詞： 講師站在鏡頭前方，抬起右手指向觀眾。攝影機保持固定位置，在講師指向鏡頭的瞬間快速變焦，從中景推至面部近景。講師露出自信笑容，最後穩定停留一秒，作為廣告結尾。 這三個鏡頭完成後，再透過影片剪輯軟體組合成完整的 15 秒短影音。為什麼我建議分開生成？因為對 AI 影片模型來說，在短短 15 秒內，同時要求多種複雜運鏡、人物動作與場景切換，容易增加生成失誤。對初學者而言，把每一個鏡頭分開設計，通常更容易控制畫面與角色一致性。 六、五個新手最容易犯的運鏡提示詞錯誤錯誤一：只寫運鏡名稱例如：「電影級推進運鏡。」問題是沒有說明起點、終點與移動速度。建議改成：「攝影機從人物中景沿直線緩慢向前推進，最後停在臉部特寫。」 錯誤二：一次塞進太多運鏡例如：「攝影機推進、環繞、甩鏡、快速變焦，最後再拉遠。」這種提示詞很容易讓 AI 不知道該優先執行哪個動作。建議新手從一個鏡頭、一種主要運鏡開始。熟悉之後，再嘗試安排連續動作。 錯誤三：沒有區分攝影機與人物的動作例如：「人物向鏡頭靠近。」這代表人物移動。但如果想做的是攝影機推進，應該寫：「人物站在原地，攝影機向前靠近人物。」這兩種效果完全不同。 現在可以使用 Meshy、Tripo AI、Hunyuan3D 等工具，將圖片轉換成 3D 模型。丟一張科幻機甲圖片給 AI，它可能很快就能生成一台看起來相當完整的機甲。 但看起來像機甲，不代表它真的具備合理的機械結構。 舉個例子，當你想讓機甲舉起右手或走路，可能發現： 肩膀和胸甲黏在一起。 手肘沒有合理的活動空間。 膝蓋彎曲時，裝甲直接穿進大腿。 腳掌沒有正確的支撐點。 走路時雙腳亂甩，整台機甲像章魚一樣。 圖片轉 3D 的 AI 主要在推測外觀與幾何形狀，不一定能建立符合設計意圖的關節、活動限制與運動方式。即使工具提供自動拆件、綁定或動畫功能，也仍然要檢查結果。 所以 AI 生成的模型，經常需要人工整理。這也是為什麼這類工作流仍需要 3D 技術背景：生成速度加快了，後續的判斷與修正並沒有全部消失。 三、如何把 AI 機甲建模拆成完整六步驟？先把整條路線放在一起： 設計參考 → 生成網格 → 整理模型 → UV 與貼圖 → 關節與骨架 → 動畫及引擎測試。 本節先說明前三步，接著再分別拆解法線、材質與可動結構。這是方便理解的順序；實作時通常要在早期先規劃拆件，並在修改拓樸後重新確認 UV 與烘焙結果。 Step 1：使用 AI 設計機甲外觀首先需要一張機甲設計圖。可以使用 ChatGPT 生成圖片，也可以使用自己繪製的角色設定圖。 建議準備正面、側面、背面；如果可以，再補充 45 度角視圖。 因為一張圖片只能提供單一視角。正面圖片看不到背後的推進器，也無法準確判斷肩甲厚度，AI 必須自己猜測。 參考視角越完整，越有機會降低幾何推測錯誤，但前提是多視角的角色設計必須一致。不能正面是圓肩甲，背面卻變成另一台機甲。 此外，不是每個 Image-to-3D 介面都能一次接收多張圖。工具支援多視角時，再依它要求的格式輸入；不支援時，其他視圖仍可用於人工檢查。 這個階段的目標，是建立一份適合 3D 建模的設計參考，而不只是漂亮的宣傳圖。 Step 2：將圖片轉換成 3D 白模接著使用 Image-to-3D 工具。可以研究以下選擇： 工具 可以研究的用途 官方入口 Meshy 圖片轉 3D、文字轉 3D、AI 材質生成 Meshy／官方文件 Tripo 完成後會得到 3D Mesh，可能可以匯出 GLB、OBJ 或其他格式，實際支援依工具與方案而定。若後續需要骨架與動畫，也要選擇能保存相關資料的匯出格式，不能只看靜態網格是否成功匯出。 這時就能在 Blender 裡旋轉模型、檢查各角度。但先不要急著上材質，下一步可能更重要。 Step 3：整理模型的網格結構這一步叫 Mesh Cleanup，也可能涉及 Retopology。 **Mesh（網格）**由頂點、邊與面組成，可以想成用許多小多邊形拼出一台機甲；**Topology（拓樸）**則是這些元素如何排列、連接。 AI 模型可能外觀漂亮，網格卻不一定適合編輯或動畫。例如： 多邊形分布不均勻，或面數過高。 有多餘的內部幾何結構。 零件黏連，無法直接當成獨立關節操作。 關節附近的網格不合理。 整理時常遇到兩種技術： 技術 主要目的 需要注意 Decimation（減面） 減少多邊形數量 不保證減完就適合變形動畫 Retopology（重新拓樸） 重新安排網格結構 更重視後續編輯、變形或烘焙需求 如果模型太複雜，後續修改、骨架設定與即時渲染都會增加成本，遊戲資產尤其需要控制複雜度。不過，只製作靜態圖片時，不一定值得花大量時間重新拓樸；以剛體零件為主的機甲，也不需要每片裝甲都使用真人角色的變形佈線。 整理到什麼程度，取決於最終用途。 四、Step 4 的法線貼圖，應該在哪個階段使用？假設我們已經生成一台精細機甲，胸甲有螺絲、散熱孔、裝甲接縫、金屬刻痕。如果全部使用真正幾何呈現，模型可能相當複雜。 其中細小刮痕、淺凹槽、在目標觀看距離下不影響輪廓的螺絲頭，可以考慮用法線貼圖模擬。這就衍生出常見的遊戲資產製作方法： High Poly → Low Poly → Normal Map，也就是高精度模型 → 低面數模型 → 烘焙法線貼圖。 假設先做一台有 100 萬個多邊形的精細機甲，再製作只有 2 萬個多邊形的簡化版本。這些數字只是示意，不是所有機甲的標準面數。 簡化後，原本的螺絲、細刻痕可能消失。這時透過 Baking（烘焙），把高模的表面方向細節轉成適用於低模的法線貼圖，再套回低模材質。 低模雖然沒有那些真正的小幾何，在光線下仍能呈現類似凹凸。這能降低幾何成本、保留許多視覺細節，也方便配合不同精細程度的模型版本。但總效能仍受貼圖記憶體、材質數量、繪製次數等因素影響，不能只比較面數。 法線貼圖不能取代哪些結構？法線貼圖不會真正改變物體輪廓。 例如肩膀上有一根長砲管，不能只靠法線貼圖讓它伸出來。大型裝甲、武器、推進器、真正的開孔與活動關節，仍然需要合理的幾何結構。 它也不會替模型增加碰撞體積；當細節需要影響輪廓、接觸或近距離視差時，就要重新評估是否應保留幾何。 AI 生成法線圖，等於高低模烘焙嗎？不等於。 AI 可以生成看起來合理的表面凹凸，但要精準保留特定高模的細節，仍需要高低模對應、低模 UV 與正式烘焙流程。不能把任意一張紫藍色圖片直接當成正確法線資料。 在 Blender 中，法線圖通常會經過 Normal Map 節點再接入材質。切線空間法線圖需要對應的 UV，圖片應設定為 Non-Color，並確認與目標引擎的法線慣例相容。可參考 Blender 官方 Normal Map 節點手冊與烘焙說明；實際介面請對照自己使用的 Blender 版本。 五、Step 4 的材質與 UV，跟法線貼圖有什麼關係？法線貼圖其實只是材質系統的一部分。在 3D 製作中，常見的是 PBR（Physically Based Rendering，物理基礎渲染）材質。 用機甲來理解： 項目 用途 機甲範例 Base Color 決定基本顏色 紅色裝甲、白色胸甲、黑色關節 Metallic 表達金屬特性 金屬裸露區與非金屬塗層的差異 Roughness 控制反射的粗糙程度 低粗糙度反射較銳利，高粗糙度較模糊 Normal 模擬細小凹凸 刻痕、淺凹槽與裝甲紋路 Emission 表達自發光外觀 眼睛、能源核心與燈條 金屬零件表面若覆有一般非金屬漆，不能只因底下是金屬，就把整片外觀都設成裸金屬。Emission 能讓表面看起來發光，但是否照亮周圍、是否產生光暈，還取決於渲染器、燈光與後製設定。 UV 展開是什麼？想像把紙盒拆開攤平成一張紙，在紙上印上顏色與圖案，最後再折回紙盒。 UV 展開建立 3D 模型表面與 2D 圖片的對應關係。如果 UV 不正確，材質就可能拉伸、錯位或出現接縫。 因此，完整材質流程通常是： 模型整理 → UV 展開 → 產生或烘焙貼圖 → 設定 PBR 材質 → 檢查成果。 這也解釋了原本「使用 GPT 生成材質貼圖」需要補上的條件：產生一張金屬紋理圖片，不等於已經完成這台機甲的材質。 圖片仍要對應 UV，或經過投射、接縫修整與烘焙；Base Color、Roughness、Metallic、Normal 也必須各司其職。不能把帶著固定高光與陰影的彩色圖片，直接當成完整的 PBR 貼圖組。 「貼圖只能 512K」是什麼意思？原分享提到的「512K」需要特別注意，因為這不是清楚的貼圖像素尺寸寫法。它可能想表達 512×512 像素，也可能在描述檔案容量；沒有原始規格，無法確定。 兩者差異很大，而且貼圖解析度也不是越低越好： 常見像素尺寸 可以考慮的情境 512×512 部分小型物件或遠距離資產 1024×1024 部分一般中小型資產 2048×2048 需要較多近距離細節的資產 4096×4096 高細節需求，同時承擔較高記憶體成本 這些只是示意，不是固定標準。應考慮觀看距離、螢幕佔比、平台效能、貼圖數量與材質需求，也要區分磁碟壓縮檔大小與 GPU 載入成本。 不能直接說「不是做電腦遊戲，就只能使用 512 的貼圖」。 六、Step 5 為什麼要拆關節，還要設定骨架？因為目前做出來的機甲，可能只是一個外觀完整的模型。要讓它走路，就必須建立合理的活動結構。 機甲跟真人角色的綁定方式不完全相同。真人手肘彎曲時，皮膚會變形；但機甲的金屬裝甲，正常情況下不應該像橡皮一樣彎曲。 所以通常要讓不同部位可以獨立控制，例如胸甲、上臂、前臂、肩關節、大腿、小腿、膝關節與腳掌。這些可以是分離物件，也可以是同一網格內彼此不連通、由不同骨骼控制的剛體區塊。 接著設定旋轉樞紐、父子階層與活動限制： 手肘在合理角度內彎曲。 膝蓋不隨意向後折。 肩膀轉動時，肩甲配合移動。 腳掌落地時維持合理的接觸位置。 如果只把表面切開，沒有補齊遮住的零件、關節間隙與樞紐，動起來仍可能穿模或露出破洞。 有些機甲只需分離零件、旋轉樞紐與父子階層，就能完成基本動作；若使用骨架，也可以讓剛性裝甲跟隨單一骨骼，不一定要像皮膚一樣做平滑蒙皮變形。軟管、線材等需要彎曲的部分，則另行處理。 **機甲建模還涉及機械結構與運動設計。**拆分不正確，即使外觀很漂亮，動畫仍可能很奇怪。 Step 6：製作動畫，並到引擎中驗收骨架設定完成，還要在時間軸上安排動作。先從抬手、屈膝、腳掌落地等簡單測試開始，再做完整走路循環。 過程中要觀察裝甲是否穿模、腳是否滑動、重心是否合理，以及匯出後的骨架、材質與動畫是否一致。最後匯入 Godot 或其他目標環境，確認尺度、方向、播放與效能，才算走完這條流程。 能在 Blender 裡播放，不代表已完成遊戲整合；遊戲中的移動控制、碰撞與動畫切換，也需要另外設定與測試。 七、三種 AI 3D 建模流程，應該怎麼選？研究到這裡，我認為應該先決定用途，再選製作流程。 方案 A：快速展示型AI 圖片 → AI 生成白模 → AI 材質 → 3D 展示。 適合科幻角色展示、產品概念設計、靜態渲染與社群作品。若用於 3D 網頁，仍要視模型大小和裝置效能做適度整理。 C：可動機甲型AI 圖片 → AI 生成白模 → 零件拆分與整理 → 關節設定 → 骨架／控制系統 → 材質 → 動畫。 適合機甲動畫、遊戲角色、戰鬥機器人與互動展示。優點是能建立真正可動的機甲；缺點是關節與動畫需要仔細調整，技術門檻最高。 這裡的排列是概念路線，不是唯一施工順序。需要改拓樸或拆件時，應先規劃好再定稿 UV 和烘焙；也可以先做簡單活動測試，再投入精細材質。     AI 短劇為什麼會紅，AI 分身帶貨卻不一定有效？搞懂 AI 影片的創意與信任

    現在 AI 影片生成技術越來越厲害，不只可以複製真人的長相、聲音，還能讓虛擬人物說話、跳舞、演戲，甚至完全不需要攝影機，就能製作出一支看起來像真人拍攝的影片。 但你有沒有想過一個問題？ 為什麼觀眾願意追一部完全由 AI 製作的短劇，卻不一定願意相信一個 AI 分身推薦的商品？ 明明都是 AI 生成的內容，為什麼效果可能差這麼多？ 其實問題不只在 AI 技術，而在於我們有沒有搞清楚 AI 應該扮演的角色。 今天就從最簡單的觀念開始，帶你理解 AI 影片真正的優勢，以及如何把這些優勢運用在短影音、AI 網紅、品牌行銷與商品帶貨。這篇談的是內容策略與觀看動機，不代表 AI 短劇一定會紅，或 AI 分身一定無法帶貨。 一、先搞懂：觀眾到底在看什麼？我們先用兩個大家比較熟悉的節目來舉例：一個是漫威電影，另一個是《木曜4超玩》的一日系列。 漫威電影：觀眾買單的是想像力在漫威電影裡，鋼鐵人可以飛天遁地，奇異博士可以打開傳送門，蜘蛛人可以在高樓大廈之間盪來盪去。 你會因為這些事情在現實生活中不可能發生，就覺得電影很假、不值得看嗎？ 當然不會！ 因為你從一開始就知道，這是一個虛構的世界。你期待的是精彩的故事、角色魅力、視覺效果，以及電影帶給你的情緒體驗。 所以即使電影大量運用特效，只要故事好看，你還是願意買票進電影院。這就是虛構娛樂內容的核心價值。 一日系列：觀眾買單的是真實體驗現在換個情境。 以下是假設情境，並非節目實際製作案例。 假設《木曜4超玩》推出一集「一日消防員」，但邰智源根本沒有到現場，而是讓 AI 分身代替他穿消防衣、爬樓梯、操作消防設備。 整支影片看起來非常真實，甚至連表情、聲音都模仿得一模一樣。你會覺得這集很精彩嗎？ 可能有人覺得 AI 技術很厲害，但原本喜歡一日系列的觀眾，恐怕會覺得少了什麼。 因為大家真正想看的，是主持人親自體驗工作的過程，包括他的反應、出糗、疲憊，以及跟現場工作人員的真實互動。 觀眾要看的不是「邰智源長什麼樣子」，而是「邰智源真的去做了什麼」。 這就是實境內容與虛構娛樂最大的差別。 同樣的問題，也發生在 AI 分身帶貨假設你看到一個 AI 分身介紹保養品： 「這款精華液我用了三個月，皮膚真的改善很多！」 結果你知道這個人根本沒有實際使用過產品，連使用前後的照片都是 AI 生成的。你還會相信這個推薦嗎？ 這就是問題所在：AI 可以複製一個人的外表，卻不能自動複製他的真實經驗。 而商品帶貨最需要的，往往就是經驗、證據與信任。 當然，這不代表 AI 分身不能帶貨。分身可以傳達已確認的產品資訊，也可以在有真實紀錄的前提下，協助本人表達經驗；但不能把生成的畫面當成實測證據，或替沒有發生的體驗背書。 你必須先搞清楚：觀眾期待的是娛樂，還是真實推薦？ 二、別只追求像真人：AI 影片有哪些值得發揮的優勢？很多人開始學 AI 影片，第一個想法都是： 「我要怎麼讓 AI 生成的影片看起來像真人拍的？」 於是開始研究人物一致性、嘴型同步、表情控制、攝影機運動、皮膚質感。這些技術當然重要。 但如果我們只是努力讓 AI 模仿真人拍片，可能反而忽略了 AI 最大的優勢。 AI 很有價值的地方，是讓過去做不到、做不起，或很難拍攝的畫面變得可行。我把這些優勢整理成五個方向。 方向一：突破物理限制，拍攝不可能的畫面想像一下： 一個普通上班族突然變成巨龍，飛越台北 101。 一名少女走進鏡子，來到另一個平行宇宙。 一位老師縮小成細胞大小，帶學生進入人體血管。 一杯咖啡突然長出手腳，跑去跟冰箱吵架。 這些畫面如果用傳統方式製作，可能需要大量特效、道具、動畫師與製作預算。但現在透過 AI 圖片與影片生成工具，個人創作者也有機會完成。 這類內容的重點，不是讓觀眾相信事情真的發生過，而是讓觀眾產生一個念頭： 「哇！這個畫面也太有趣了吧！」 這就是 AI 最直接的創意優勢。 **適合應用：**奇幻短劇、科幻故事、超現實廣告、動漫 IP、AI 音樂 MV。 方向二：讓商品變成角色，而不是只會被介紹傳統商品廣告通常是主持人拿著商品，介紹功能、特色與價格。但如果我們換一種方式呢？ 假設你要賣一台掃地機器人。 傳統拍法： 「這台掃地機器人具有智慧避障功能，還能自動清潔地板。」 AI 劇情拍法：一台掃地機器人半夜偷偷召開家庭會議，它憤怒地說： 「我每天幫你們打掃，結果你們連襪子都不撿！」 沙發回答： 「至少你還能移動，我已經被坐十年了！」 最後主人突然開燈，所有家具立刻恢復原狀。 這就是把商品角色化。商品不再只是被動介紹的物件，而是具有個性、情緒與故事的角色。這種方法非常適合 AI 品牌短劇。 但有一點要注意：劇情可以虛構，產品功能不能亂編。 上面的功能介紹只是示例，實際拍攝仍應依該款商品已確認的規格；如果最後要帶回商品賣點，必須使用真實且可驗證的產品資訊。 方向三：把抽象知識變成看得懂的畫面這個方向，我認為特別適合知識型創作者與教育工作者。 例如，你想教學生什麼是 AI Agent。傳統教學可能會使用簡報，解釋 Agent、Tools、Memory、Workflow 等名詞。 但如果透過 AI 動畫呢？你可以把 AI Agent 設計成一位辦公室主管。他收到任務後，開始指揮不同部門： 搜尋部門負責找資料。 分析部門負責整理資訊。 設計部門負責製作圖卡。 審核部門負責檢查成果。 學生就能透過故事理解任務分工與工具協作。這是一種教學比喻，不代表每個 AI Agent 都有這些部門或相同架構。 同樣的概念也能用在醫療衛教、金融知識、歷史事件、科學教育與企業教育訓練，內容本身仍要經過適當的專業查核。 這類影片的優勢，是讓觀眾看見原本看不見的概念。AI 不只是幫你做影片，而是把知識變成可以觀看的故事。 方向四：建立自己的虛擬 IP 宇宙這也是我認為 AI 網紅未來很值得發展的方向。 很多人建立 AI 網紅，只是讓一個漂亮的虛擬人物每天換衣服、拍照、介紹商品。這當然可以做。 但問題是，如果你的 AI 網紅跟真人網紅做的事情完全一樣，那觀眾為什麼一定要看你的 AI 網紅？ 我們不妨換個方向。 假設你建立了一位 AI 虛擬女主角，她表面上是普通上班族，但其實來自未來世界。白天她會分享穿搭、咖啡、日常生活，晚上卻會接到來自平行宇宙的任務。 她可能因為不熟悉人類生活，經常誤解日常對話，鬧出各種笑話。 這樣一來，你的 AI 網紅就不只是漂亮的虛擬模特兒。她開始擁有角色設定、個性、世界觀，以及讓觀眾期待的故事。 這才是 IP 經營，因為觀眾追蹤的不只是外表，而是角色本身。 方向五：大量測試不同創意，而不是只大量生產影片AI 還有一個值得運用的優勢：快速產出多種創意版本，讓團隊有機會降低測試成本。實際成本仍取決於生成成功率、重做次數與後製需求。 例如，同一個商品，你可以規劃： 搞笑反轉版。 奇幻冒險版。 情侶對話版。
